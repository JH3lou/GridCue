## How the work is run

**Sub-agents, not a workflow.** The five PRs stack, so they run one after another. Inside each PR the stages are also in order: label, build, review, gate. Between stages the lead checks labels and runs the held-out set, and those checks decide what happens next. A fixed script can't make that call, so the lead starts each agent by hand.

**Every PR follows the same five stages.**

1. **Label.** A labeller writes the dev set and the held-out set from the spec section alone, before any code. It never sees the code under test. The lead spot-checks the labels.
2. **Build.** A builder sees the dev set, never the held-out set. It writes tests first, then the code, and runs the gate.
3. **Held-out run.** The lead runs the held-out set and reports the numbers as they are. A wrong view sends the work back to the builder with the failing class described, not the failing sentence. The held-out set then joins the repo as a regression set, and any later round gets a new held-out set.
4. **Review.** A reviewer sees the diff and the spec section, and nothing else.
5. **Gate.** `pnpm lint`, then `pnpm check`. UI PRs are also checked in a real browser, light and dark.

**Models, chosen by what a mistake costs.**

| Work | Model | Why |
| --- | --- | --- |
| The Local Resolver's grammar and trust flow; the View Sentence's wording against the round trip | Fable | The hardest reasoning here, and a mistake is a wrong view |
| Parser, Mentions, compiler, and Controller changes; every review | Opus | Subtle code with wrong-view risk, on well-defined rules |
| Labelling; hooks; both UIs; examples; Site docs; the agent skill | Sonnet | Well-specified work with tests to hold it |
| Changelog lines, index entries, link checks | Haiku | Mechanical |

**Branches.** Each PR is a branch stacked on the one before: `fix/reading-wrong-views`, `feat/as-you-type`, `feat/view-sentence`, `feat/local-resolver`, `feat/terse-requests`. The planning record (the grill log, this plan, the spec, ADRs 0020 and 0021, `CONTEXT.md`) is its own small docs PR, so the fix PR holds one concern. The owner asked on 2026-11-10 for each PR to be committed and opened as it passes its gate.

**Live runs.** No sub-agent calls Jev. The owner approved one live run before PR 1 merges; the one before PR 5 waits for the owner's command.
