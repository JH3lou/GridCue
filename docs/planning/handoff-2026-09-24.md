## Owner decisions made during the build

- **Dark mode.** It applies to the whole page in both examples, following `prefers-color-scheme`, not just the command bar.
- **Workers support.** `gridcue/server` resolves to the real module under `workerd` and `edge-light`. `browser` keeps the refusing stub, and `worker` is deliberately absent. See ADR 0011. Whether `@typesafe-ai/sdk` runs under workerd is unverified until a real Wrangler build.
- **Confidence bands.** Families and enum/boolean values now use the same three bands as column picks: use the value at or above `ready`, ask between `clarify` and `ready`, drop it below `clarify`. Unsupported families at or above `clarify` are still refused, not confirmed.
- **Question budget.** The Jev provider asks about 27 questions per step on the 9-column wealth schema. With `maxQuestions` 96, that allows about 3 steps per request. This is accepted for the MVP but must be extended; see the next section.
- **PR shape.** The owner asked for one PR for the whole first build.

   **First live run, 2026-09-24:** `pnpm test:live` passes. `pnpm eval:live` gives 4 exact, 1 safe abstention, 4 rejected, 6 mismatch, and **0 unsafe**. Every mismatch asked a question instead of applying; none applied a wrong view. Each step costs 27 questions on the wealth schema, and the median call takes 207 ms (range 160 to 601 ms).

   The mismatches have three causes:
   - **Jev says yes to more than one kind of change.** Jev asks one yes/no question per family, and several can come back yes at once.
     - "Show accounts over $1 million": filter 0.97 and show-columns 0.85, so GridCue asks the User to split the request.
     - "Keep only account, household, …": show-only 0.97, hide 0.89 and show 0.70.
     - "Clear the filters and sorting": both clears 0.99, plus reset 0.78.
     - "Reset the view": reset 0.96, plus clear-filters 0.84.

     The compiler needs rules for which family wins. Show-only already covers show and hide. Reset covers the clears, but explicit clears should win over a weaker reset. Alternatively, Jev could ask a Choice for the step's main kind of change. That changes confirmation behaviour, so write an ADR first.
   - **Column aliases land in the middle band.** "Only Roth accounts, grouped by rep" gives Registration type 0.78 and Advisor 0.73, so GridCue asks about both. Set `ready` from more live cases than these 15; any change to the confidence defaults needs an ADR.
   - **No unknown-term detection.** Jev always returns `unmatchedTerms: []`. "Sort by risk score" therefore asks "Which column should be sorted by?" instead of saying there is no "risk score" column. That is still safe, but less helpful.

## Open follow-ups

**Not fixed, but deliberately safe as they stand:**

- `RowsAdapter.getState` returns the live object. Cloning it would break the `useSyncExternalStore` identity.
- Neither example disposes the controller on unmount. A simple `useEffect` cleanup would break under StrictMode's double mount, and the TanStack adapter also needs a `dispose`.
- In `apply()`, some adapter calls run before its try/catch: `getState`, `getCapabilities`, and `getDefaultState`. The same is true of `getState` in `undo()`. If one throws, the controller can still be left stuck on "applying". When `apply` throws partway through a write, nothing restores the previous view.
- Answering "No" to a family or value confirmation leads to a clarification with no options. It fails closed, and the User rephrases through "Edit request".
- Two value-clarification ids can collide when column or value ids contain dots. That is harmless, because one answer cannot confirm the other value.
- The TanStack adapter refuses OR and nested filter trees. The compiler never emits them, but the Site docs should say so.
- The Host's `ConfidencePolicy` reaching audit events has no end-to-end test.

**Gaps against the spec:**

- The Next example has no developer panel, and the Vite panel lacks before and after View State (spec section 7).
- A provider timeout ends in "error", not in idle with the Utterance kept (section 9).
- The handler has no auth hook. The docs should tell Hosts to put it behind their own auth and rate limits.
- `examples/vite/server.ts` (`pnpm start`) does not load `.env`.

**Cosmetic:**

- `biome migrate` for the `recommended` key.
- Duplicated percent and currency formatting.
- `optionsFor` takes a string.
- Type `FAMILY_PHRASE` as `Record<Family, string>`.
