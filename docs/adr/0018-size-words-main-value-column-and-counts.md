# Size words, the main value column, and counts

A Host found four gaps in one request, "show top accounts grouped by household sorted largest to smallest" (2026-10-27). GridCue 0.1.0 kept only "Group by Household": the part's first verb family swallowed "sorted", "largest to smallest" read as no direction (so it sorted ascending), "top" named no column, and there was no way to ask for ten rows. Four additive changes close them. None changes an existing meaning, so the protocol stays at 0.1.

- **Mid-line parts.** Code also splits a part where a different kind of change starts mid-line, with no comma or "and": "sorted", "grouped", "ordered" before "by" or a direction, and "show", "only", "filter", "where". It splits only when the text before already gives an instruction with words after its verb, and only between different kinds of change. "Roth IRAs grouped by rep" stays one part, since its value describes the rows (ADR 0013), and "show accounts where value is over $1M" stays one part, since "show" and "where" both choose rows. Nothing inside a quoted value starts a part, sets a direction, or reads as a size word or a count.
- **Direction phrases.** "Largest to smallest", "biggest to smallest" and a size word alone ("top", "largest", "biggest") sort descending; "smallest to largest" and "smallest" ascending. The "X to Y" phrases are read first, so "smallest to largest" is never read as "largest". A size word inside a column or value the part names ("show top tier", where "Top tier" is a value) is part of that name, not a direction.
- **`defaultMeasure`.** A schema may name its main value column. A size word with no column named sorts by it, and the plan records the Host's choice as evidence (`c0.measure`, source `host`). Without one, or when it is restricted or can't sort, GridCue asks which column, as before. A name GridCue doesn't know ("sort by risk, largest first") is still asked about: the measure fills a missing column, never an unknown one or a named one that can't sort.
- **`limit.set`.** A count after a size word ("top 10", "largest 5", "top 10,000") is a count, never a filter value. It becomes `{ type: "limit.set", count }`, with its own preview line, only where the adapter lists `limit.set`. A grid whose rows come a page at a time can't show the true first ten, so it doesn't list it: the plan then sorts alone, keeps the count as `dropped:` evidence, and the Preview's `notes` say the count was not applied. Nothing is dropped silently. `ViewState.limit` is optional, so adapters that never limit are unchanged. The Rows Adapter supports it; the TanStack Table adapter does not yet.

Column synonyms need no new field: `aliases` already match as whole words (ADR 0013), so a Host supplies "aum" and "size" for Market value there.
