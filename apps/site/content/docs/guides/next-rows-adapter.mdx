---
title: Next.js with the Rows Adapter
description: Keep rows in memory, render them with any table, and answer requests from a Next.js route handler.
---

Use the **Rows Adapter** when your app holds its rows in memory and renders its own table, with no grid library. GridCue keeps the View State. `applyView` turns that state and your rows into what to render.

The finished version is `examples/next` in the GridCue repo: a plain HTML table, no Tailwind. Run it with `pnpm dev:next`.

## Install

```bash
npm i gridcue @typesafe-ai/sdk
```

`@typesafe-ai/sdk` is only needed for Jev, and only on the server.

## Describe the columns

`defineSchema` builds the **View Schema** from your column IDs and labels. Declare what can't be inferred without sample rows: kinds, enum values, aliases, and restricted columns.

```ts
// lib/accounts-schema.ts
import { defineSchema, emptyViewState } from "gridcue";

export interface Account {
  account_number: string;
  advisor_name: string;
  registration_type: "taxable" | "ira" | "roth_ira";
  market_value: number;
  tax_id: string;
}

const columns = [
  { id: "account_number", label: "Account number" },
  { id: "advisor_name", label: "Advisor" },
  { id: "registration_type", label: "Registration type" },
  { id: "market_value", label: "Market value" },
  { id: "tax_id", label: "Tax ID" },
];

export const schema = defineSchema(columns, {
  rowNoun: "account",
  restricted: ["tax_id"],
  columns: {
    advisor_name: { aliases: ["advisor", "rep"] },
    registration_type: {
      enumValues: [
        { id: "taxable", label: "Taxable" },
        { id: "ira", label: "IRA" },
        { id: "roth_ira", label: "Roth IRA", aliases: ["roth"] },
      ],
    },
    market_value: { kind: "currency", aliases: ["value", "balance"] },
  },
});

/** Start with every column visible except the restricted one. */
export const initialState = {
  ...emptyViewState(columns.map((c) => c.id)),
  visibleColumnIds: columns.map((c) => c.id).filter((id) => id !== "tax_id"),
};
```

A restricted column is never sent to a provider and never acted on. A request that names it is refused. See [Safety](/docs/safety).

## Render the view

The Controller and the adapter live in a client component. Create them once with a `useState` initializer, so re-renders don't rebuild them:

```tsx
// app/accounts-view.tsx
"use client";

import { applyView, createGridCue, createRemoteProvider, createRowsAdapter } from "gridcue";
import { GridCueBar } from "gridcue/react";
import { useState, useSyncExternalStore } from "react";
import { type Account, initialState, schema } from "@/lib/accounts-schema";

export function AccountsView({ rows }: { rows: Account[] }) {
  const [{ adapter, cue }] = useState(() => {
    const adapter = createRowsAdapter({ schema, initialState });
    return { adapter, cue: createGridCue({ adapter, provider: createRemoteProvider({ endpoint: "/api/gridcue" }) }) };
  });
  const { state } = useSyncExternalStore(adapter.subscribe, adapter.getState, adapter.getState);
  const view = applyView(rows, state, schema);
  const label = (id: string) => schema.columns.find((c) => c.id === id)?.label ?? id;

  return (
    <main>
      <GridCueBar controller={cue} />
      <table>
        <thead>
          <tr>
            {view.columns.map((id) => (
              <th key={id}>{label(id)}</th>
            ))}
          </tr>
        </thead>
        <tbody>
          {view.rows.map((row) => (
            <tr key={row.account_number}>
              {view.columns.map((id) => (
                <td key={id}>{String(row[id as keyof Account])}</td>
              ))}
            </tr>
          ))}
        </tbody>
      </table>
    </main>
  );
}
```

`createGridCue` takes the schema from the adapter when you don't pass one.

`applyView(rows, state, schema)` is pure. It returns:

| Field | What it holds |
| --- | --- |
| `columns` | Visible column IDs, in display order |
| `rows` | The filtered and sorted rows |
| `pinned` | The visible columns pinned to the start and to the end, `{ start, end }`, each in its pin order |
| `density` | `"compact"`, `"comfortable"` or `"spacious"` |
| `totals` | One for each total the view holds, `{ columnId, function, value }`, over every row it shows. `[]` when there are none. `value` is `null` when no row has a value |
| `groups` | Present only when the view is grouped: one entry per distinct key, `{ key, rows, totals }`, in one order: by the total when the sort is on a column with a total, else the order the groups first appear in your rows ([details](/docs/api/adapters#one-group-order-in-both-adapters)) |

To render groups, loop over `view.groups` when it is set and render each group's `rows`, as `examples/next` does. A group's `totals` and the view's `totals` are there for a table that draws them (see below); a table that doesn't can ignore them.

Import the stylesheet once, in the root layout:

```tsx
// app/layout.tsx
import "gridcue/styles.css";
```

### Your own controls

When the User clicks a column header, change the view through the adapter, so GridCue sees the change and bumps the Revision:

```ts
adapter.setState((s) => ({ ...s, sorts: [{ columnId: "market_value", direction: "desc" }] }));
```

A pending Preview built on the old Revision is then refused instead of overwriting the User's change.

`createRowsAdapter` also takes `maxSorts` (default 3), `maxGroups` (default 2) and `renders`. `initialState` is what "reset the view" returns to.

### Pinning and density

GridCue can pin columns and set the density, when your table draws them. The adapter lists those two operations only when you say so with `renders`, and the default is none: "pin account number" then asks "This grid can't pin columns." and changes nothing. The Rows Adapter hands your table what to draw in `view.pinned` and `view.density`, and `view.columns` already puts the start-pinned columns first and the end-pinned ones last.

Turn on only what your table draws. Pins need your markup to keep those columns in place while the rest scroll. Density needs your own row height and cell spacing:

```tsx
const adapter = createRowsAdapter({ schema, initialState, renders: ["pinning", "density"] });
```

GridCue can't see what your markup draws. A Host that names one it doesn't draw gets a Preview and "View updated." with nothing to see. See [Adapters](/docs/api/adapters#renders).

### Totals

GridCue can show a total for each group, or one for the whole view when it isn't grouped. The adapter lists `aggregation.set` only when you say so with `renders: ["totals"]`, and the default is none: "total market value by advisor" then asks "This grid can't show totals." and changes nothing.

Turn on `"totals"` only when your table draws them: a value for each group beside its rows, from `group.totals`, and for an ungrouped view one total from `view.totals`. Show the value as a total, with a word such as "total" or "avg" beside it, so a User doesn't read it as a row's own value. An empty total is `null`: draw nothing, never 0.

```tsx
const adapter = createRowsAdapter({ schema, initialState, renders: ["totals"] });
const view = applyView(rows, state, schema);

view.groups?.map((group) => group.totals); // [{ columnId: "market_value", function: "sum", value: 12_400_000 }]
view.totals; // the same, over every row the view shows
```

**The group order changed.** `applyView` now orders a grouped, sorted view's groups as TanStack Table does: by the total when the sort is on a column with a total, else in the order the groups first appear in your rows. Before, it ordered them by the sorted rows, so a descending sort on Market value put first the group that held the largest single row. A grouped, sorted view can draw its groups in a different order from before, with no change to its View State. See [one group order](/docs/api/adapters#one-group-order-in-both-adapters).

## Let a request name a value

With `localValues`, "Avery Lane's accounts" filters Advisor to that advisor, and "the Alder household" filters Household. The Rows Adapter holds the view and not your rows, so you pass the values yourself, from the rows the component already has:

```tsx
const [{ adapter, cue }] = useState(() => {
  const adapter = createRowsAdapter({ schema, initialState });
  const localValues = {
    advisor_name: () => rows.map((row) => row.advisor_name),
    household: () => rows.map((row) => row.household),
  };
  return {
    adapter,
    cue: createGridCue({ adapter, provider: createRemoteProvider({ endpoint: "/api/gridcue" }), localValues }),
  };
});
```

- **The values are read in the browser and never sent.** The route handler gets the same request with `localValues` on or off. A name the User types is in the request, as any word is. See [Safety and protocol](/docs/safety#the-data-boundary).
- **Name the columns that hold names,** an advisor or a household, as text columns that are not restricted. A key for any other column makes `createGridCue` throw `INPUT_CONFIG`.
- **GridCue keeps its index while a function returns the same array.** The form above builds a new array on every request, which is cheap for a few thousand rows. For more, return one array until your rows change.
- **The `useState` initializer reads `rows` once.** If your rows change, read them through a ref, so each function sees the current array.
- **A grid that pages from a server holds only its page.** Return your own list of every name instead.

With the fixture's rows, "Avery Lane's accounts" previews `Filter Advisor to exactly “Avery Lane”`, and "Lane's accounts" asks "Did you mean Advisor: Avery Lane?" with "Yes, Avery Lane" and "No". See [Requests](/docs/concepts/requests#local-values) for what reads and what asks, and [`createGridCue`](/docs/api/create-grid-cue#local-values) for the option.

## The route handler

`createGridCueHandler` returns a Fetch-standard `(request: Request) => Promise<Response>`, which is exactly what a Next.js route handler exports:

```ts
// app/api/gridcue/route.ts
import { createMockProvider } from "gridcue/mock";
import { createGridCueHandler, createJevProvider } from "gridcue/server";

const apiKey = process.env.JEV_API_KEY;

/** Jev when JEV_API_KEY is set on the server, the Mock Provider otherwise. */
export const POST = createGridCueHandler({
  provider: apiKey ? createJevProvider({ apiKey }) : createMockProvider(),
});
```

The key stays in the route handler's environment. Never name it `NEXT_PUBLIC_JEV_API_KEY`: that prefix copies it into the browser bundle. `gridcue/server` throws if a client component imports it.

Before you ship, wrap the handler in your session check and rate limit. See [Protect the endpoint](/docs/guides/protect-the-endpoint).
