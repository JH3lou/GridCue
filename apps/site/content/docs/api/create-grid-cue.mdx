---
title: createGridCue
description: The Controller that wires a grid, a schema and an Intent Provider together, and the state it exposes.
---

`createGridCue` is the one object a Host creates to connect a grid to GridCue. It takes a Grid Adapter and an Intent Provider, turns each Utterance into a View Plan, shows a Preview, asks a Clarification when it is unsure, and applies or undoes the change through the adapter. It lives in the main `gridcue` entry.

## createGridCue

```ts
import { createGridCue } from "gridcue";

function createGridCue(options: GridCueOptions): GridCueController;
```

```ts
import { createGridCue, createRemoteProvider, createRowsAdapter } from "gridcue";

const adapter = createRowsAdapter({ schema });
const cue = createGridCue({
  adapter,
  provider: createRemoteProvider({ endpoint: "/api/gridcue" }),
});

await cue.propose("taxable accounts over $1M, largest first");
if (cue.getState().status === "ready") await cue.apply();
```

## GridCueOptions

```ts
interface GridCueOptions {
  adapter: GridAdapter;
  provider: IntentProvider;
  schema?: ViewSchema;
  confidence?: ConfidencePolicy;
  audit?: { onEvent: (event: AuditEvent) => void; policy?: AuditPolicy };
  maxUtteranceLength?: number;
  providerTimeoutMs?: number;
  localValues?: LocalValues;
  now?: () => Date;
}
```

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `adapter` | `GridAdapter` | required | The Grid Adapter that reads and writes the grid's view. See [Adapters](/docs/api/adapters). |
| `provider` | `IntentProvider` | required | The Intent Provider that resolves each Clause. See [Providers](/docs/api/providers). |
| `schema` | `ViewSchema` | `adapter.getSchema()` | The schema GridCue plans and validates against. |
| `confidence` | `ConfidencePolicy` | `{ ready: 0.85, clarify: 0.65 }` | Confidence bands. A decision at or above `ready` is used as-is; below `clarify` it is discarded; between the two, GridCue asks a Clarification. Both fields are required when you pass it. |
| `audit` | `{ onEvent, policy? }` | none | Receives one `AuditEvent` each time a plan is applied, cancelled, rejected, undone or fails. See [Audit events](#audit-events). |
| `maxUtteranceLength` | `number` | `500` | Longest Utterance accepted, in characters, after trimming. A longer one sets status `error` with the issue `INPUT_TOO_LONG`. At most 2000, the protocol's limit; a larger value makes `createGridCue` throw `INPUT_CONFIG`. |
| `providerTimeoutMs` | `number` | `8000` | How long the provider may take before GridCue gives up and returns to `idle` with the request kept. `0` turns the limit off. |
| `localValues` | `LocalValues` | none | A function for each text column whose values GridCue may read from your rows, in the browser, so a request can name a value: "Avery Lane's accounts". Off unless set. See [Local Values](#local-values). |
| `now` | `() => Date` | The system clock | The clock a relative date in a request is worked out from. See [now](#now). |

`DEFAULT_CONFIDENCE` is exported with the default bands:

```ts
interface ConfidencePolicy {
  /** At or above this, a decision is used as-is. Default 0.85. */
  ready: number;
  /** Below this, a decision is discarded. Between the two, GridCue asks. Default 0.65. */
  clarify: number;
}

const DEFAULT_CONFIDENCE: ConfidencePolicy = { ready: 0.85, clarify: 0.65 };
```

For how the bands shape Clarifications, see [Providers and confidence](/docs/concepts/providers-and-confidence).

## Local Values

`localValues` lets a request name a value your rows hold. With it set, "Avery Lane's accounts" filters Advisor to exactly "Avery Lane". Without it, the same request asks what to filter on. A value is read in the browser by GridCue's own code and is never sent to an Intent Provider: see [Safety and protocol](/docs/safety#the-data-boundary).

```ts
type LocalValues = Record<string, () => readonly unknown[]>;
```

```ts
const cue = createGridCue({
  adapter,
  provider,
  localValues: {
    advisor_name: () => rows.map((row) => row.advisor_name),
    household: () => rows.map((row) => row.household),
  },
});
```

The keys are column ids. Each function returns that column's values from your own rows. For a TanStack Table, [`localValuesFromTable`](/docs/api/adapters#localvaluesfromtable) builds the object for you.

- **Which columns.** A key must name a text column of the schema that is exposed (not `restricted`, and not `exposeToProvider: false`) and whose `capabilities` include `filter`. If the column sets `allowedOperators`, they must include `eq` and `in`: a value is filtered as exact text, so a column limited to `contains` can't take one. Anything else makes `createGridCue` throw `INPUT_CONFIG` with the reason: "localValues names “nope”, which is not a column of this grid.", "localValues can read only text columns, and Market value isn't one.", "localValues can't read Tax ID: it is restricted.", "localValues can't read Advisor: it may not be filtered.", "localValues can't read Advisor: a value is filtered as exact text, and its allowedOperators leave out “eq” or “in”.". So does a value that is not a function, and a `localValues` that is not a plain object, such as a `Map`. Name the columns that hold names: an advisor, a household, a counterparty. A column with a few approved values, such as Registration type, belongs in `enumValues`.
- **The function is synchronous.** GridCue calls each one when a request is made, in the browser. It drops values that are not text, that hold no letter or digit, or that repeat an earlier one, and builds a word index. It keeps the index while the function returns the same array, so return the same array while your rows haven't changed. A function that builds a new array on every call makes GridCue index it again on every request.
- **A paged grid supplies its own list.** GridCue reads what the function returns, not what the grid shows. If the grid holds one page of a larger table, return the Host's own list of every name, from a store you already hold in the browser, and not that page. A name the function doesn't return is never read.
- **A function that throws stops the request.** The status is `error`, with the issue `INPUT_LOCAL_VALUES` and the message "Couldn't read this grid's values. The view hasn't changed." The same happens when a function returns something that is not an array. The provider is not called, and GridCue never reads a request with half its values.
- **The request is built first.** The request to the provider is built before any value is looked at, and the provider is called once whether or not a request matched a value. See [Safety and protocol](/docs/safety#the-data-boundary).

How a request reads a value, and which requests ask, is on [Requests](/docs/concepts/requests#local-values).

## now

```ts
const cue = createGridCue({ adapter, provider, now: () => new Date("2026-11-13T15:00:00Z") });
```

A request such as "entries booked in the last 90 days" is worked out once, when it is made, from today's date in the schema's [Calendar](/docs/api/schema#calendar). The view keeps the two fixed days, not the words: see [Views](/docs/concepts/views#a-view-keeps-fixed-dates). `now` is the clock. Leave it out for the system clock. Tests pass a fixed one, so today doesn't move under them.

- **It is called at most once for a request,** and only for a request that holds a relative date form ("today", "last 90 days", "this quarter", "YTD"). A request with no date, or with an ISO date, never calls it.
- **Today is the day that instant falls on in the Calendar's `timeZone`.** At 2026-11-13T15:00:00Z it is 2026-11-13 in `America/New_York` and in `UTC`, and 2026-11-14 in `Pacific/Auckland`.
- **A clock that fails stops the request.** If `now` throws, or returns anything but a valid `Date`, the status is `error` with the issue `INPUT_CLOCK` and the message "Couldn't read today's date. The view hasn't changed." The provider is not called and the view does not change. Nothing guesses a date.

## GridCueController

```ts
interface GridCueController {
  getState(): ControllerState;
  subscribe(listener: () => void): () => void;
  propose(text: string, options?: { channel?: "typed" | "dictated" | "api" }): Promise<ViewPlan | null>;
  answer(clarificationId: string, optionId: string): ViewPlan | null;
  apply(): Promise<boolean>;
  cancel(): void;
  undo(): Promise<boolean>;
  dispose(): void;
}
```

### getState

```ts
getState(): ControllerState;
```

Returns the current `ControllerState`. The object is replaced, never mutated, on each change, so it works as a `useSyncExternalStore` snapshot.

### subscribe

```ts
subscribe(listener: () => void): () => void;
```

Calls `listener` after every state change, including changes the Controller picks up from the adapter (for example a User clicking a column header, which can change `canUndo`). Returns a function that removes the listener.

### propose

```ts
propose(text: string, options?: { channel?: "typed" | "dictated" | "api" }): Promise<ViewPlan | null>;
```

Turns an Utterance into a View Plan and a Preview.

- The text is trimmed. Empty text returns `null` and changes nothing.
- A new call aborts any request still in flight, silently.
- Text longer than `maxUtteranceLength` sets status `error` with the issue `INPUT_TOO_LONG` and returns `null`.
- More than 12 Clauses sets status `error` with the issue `INPUT_TOO_COMPLEX` and returns `null`.
- While the provider works, status is `resolving`.
- If a Clause names a restricted column, the provider is not called at all; the plan comes back `unsupported`.
- If the provider takes longer than `providerTimeoutMs`, status returns to `idle` with the Utterance kept, the message "That took too long. Try again." and the issue `PROVIDER_TIMEOUT`. The call returns `null`.
- If a `localValues` function throws, status is `error` with the issue `INPUT_LOCAL_VALUES`, the provider is not called and the view doesn't change. See [Local Values](#local-values).
- If the provider throws, status is `error` with the provider's `GridCueError` code (or `PROVIDER_FAILED`). A result that does not match `ResolutionResult` gives `PROVIDER_MALFORMED`.

Otherwise it returns the compiled `ViewPlan` and sets status from it:

| Plan outcome | Status |
| --- | --- |
| `ready` and it passes validation | `ready`, with a `preview` |
| `ready` but validation fails | `unsupported`, with `issues` from validation |
| `needs_clarification` | `needs_clarification`, with `message` set to the first Clarification's prompt |
| `unsupported` | `unsupported`, with a message naming the part it can't do |

`channel` is recorded on the plan's `source.channel`. Default `"typed"`.

### answer

```ts
answer(clarificationId: string, optionId: string): ViewPlan | null;
```

Answers a Clarification on the current plan and compiles the plan again with that answer, without calling the provider again. Returns the new plan, which may be `ready` or may ask another Clarification. Returns `null` and does nothing when the status is not `needs_clarification`, the Clarification ID is unknown, or the option ID is not one of that Clarification's options.

### apply

```ts
apply(): Promise<boolean>;
```

Applies the ready plan through the adapter. Returns `true` when the view changed.

- Does nothing and returns `false` unless the status is `ready`.
- Sets status `applying`, then validates the plan again against the grid's current state. If the view changed since the Preview, status becomes `error` with the message "The view changed since this preview. Preview the request again." and nothing is applied.
- If the adapter returns a failure, status becomes `error` with the adapter's code and nothing is changed.
- If the adapter throws part-way, the Controller restores the previous view only when nothing else has changed it since; otherwise it leaves the view as it is. The issue code is `ADAPTER_FAILED`.
- On success, status becomes `applied` with the message "View updated." and the change can be undone.

### cancel

```ts
cancel(): void;
```

Aborts any request in flight, drops the current plan and returns to `idle`. The Utterance is kept so the User can edit it. If a plan was showing and had not been applied, an audit event with outcome `cancelled` is sent.

### undo

```ts
undo(): Promise<boolean>;
```

Restores the view from before the last apply. Returns `true` on success, with status `idle` and the message "Change undone."

GridCue keeps one undo step. Undo works only while the grid is still at the revision the apply produced: if anything changed the view since, undo is refused with the issue `PLAN_STALE_REVISION`, so it can never erase a newer change. `canUndo` in the state tells you whether undo is available right now.

### dispose

```ts
dispose(): void;
```

Aborts any request in flight, unsubscribes from the adapter and removes every listener. Call it when the grid unmounts.

## ControllerState

```ts
interface ControllerState {
  status: InteractionStatus;
  utterance: string;
  plan: ViewPlan | null;
  preview: Preview | null;
  message: string | null;
  issues: Issue[];
  canUndo: boolean;
}
```

| Name | Type | Description |
| --- | --- | --- |
| `status` | `InteractionStatus` | Where the current request is. See below. |
| `utterance` | `string` | The trimmed text of the current request. |
| `plan` | `ViewPlan \| null` | The compiled View Plan, when there is one. See [Protocol](/docs/api/protocol#viewplan). |
| `preview` | `Preview \| null` | What the plan will change, when it has operations. Cleared while a Clarification is open. |
| `message` | `string \| null` | A short, User-facing message for the current status. |
| `issues` | `Issue[]` | Problems found, each with a stable `code`, a `message` safe to show Users and an optional `path`. |
| `canUndo` | `boolean` | `true` when the last apply can be undone: the grid is still at the revision that apply produced. |

`Preview` has three fields:

```ts
interface Preview {
  /** One line per operation, in order. */
  lines: string[];
  /** Where the plan differs from the request's words. Not operations, so never lines. */
  notes?: string[];
  /** The whole preview as one sentence, ending with the no-data-change assurance. */
  text: string;
}
```

A note says something the User should read before applying:

- "Count not applied: this grid can't show only the first 10", when the request gave a count and the grid can't limit rows.
- "Rows with no Market value are hidden too", when the request left rows out ("exclude accounts over $1M") and the filter that keeps the rest also drops rows with no value in that column.

`renderPreview` always sets `notes`, and `text` includes them. A custom UI that shows `lines` should show `notes` too; the built-in bar and the registry's `PreviewPanel` do.

The Preview is deterministic: the same plan always gives the same text, and `text` always ends with "No records will be changed."

## InteractionStatus

```ts
type InteractionStatus =
  | "idle"
  | "resolving"
  | "ready"
  | "needs_clarification"
  | "unsupported"
  | "applying"
  | "applied"
  | "error";
```

| Value | Meaning |
| --- | --- |
| `idle` | No request, or the last one was cancelled, undone or timed out. |
| `resolving` | The Intent Provider is working on the request. |
| `ready` | A valid plan with a Preview is waiting for the User to apply it. |
| `needs_clarification` | GridCue needs the User to pick an option before it can plan. |
| `unsupported` | The request asks for something GridCue can't do here: a data edit, a restricted column, or a change this grid doesn't allow. |
| `applying` | The adapter is applying the plan. |
| `applied` | The view changed. |
| `error` | Something failed. `message` and `issues` say what. |

## Audit events

Pass `audit.onEvent` to record what Users apply. Events carry no values, labels or text unless the Host opts in with `audit.policy`.

```ts
interface AuditPolicy {
  /** Include the raw request text. Off by default. */
  includeText?: boolean;
  /** Include column IDs and operators. Values are never included. Off by default. */
  includeStructure?: boolean;
}

type AuditOutcome = "applied" | "cancelled" | "rejected" | "undone" | "failed";

interface AuditEvent {
  type: "gridcue.plan";
  outcome: AuditOutcome;
  protocolVersion: string;
  planId: string;
  status: "ready" | "needs_clarification" | "unsupported";
  operationTypes: string[];
  confidenceBand: "high" | "medium" | "low" | "none";
  baseRevision: string;
  newRevision?: string;
  errorCode?: string;
  text?: string;
  structure?: Array<{ type: string; columnIds: string[]; operator?: string }>;
}
```

`confidenceBand` is worked out from the plan's confidence and the Controller's `confidence` bands: `high` at or above `ready`, `medium` at or above `clarify`, `low` below, and `none` when the plan has no confidence.

```ts
const cue = createGridCue({
  adapter,
  provider,
  audit: { onEvent: (event) => log.info(event), policy: { includeStructure: true } },
});
```
