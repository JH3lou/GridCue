A `ViewSchema` tells GridCue which columns exist, what kind of data each holds, what the User may do with each, and which names the Intent Provider may see. You rarely write one by hand: build it with `defineSchema` from the columns your table already has, or with `schemaFromTanStack` from a TanStack Table.

## defineSchema

```ts
import { defineSchema } from "gridcue";

function defineSchema(columns: readonly ColumnInput[], options?: SchemaOptions): ViewSchema;

interface ColumnInput {
  id: string;
  label?: string;
  kind?: ColumnKind;
}
```

Builds a `ViewSchema` from a list of columns and per-column additions. For each column:

- **label** is the override's `label`, else the input's `label`, else the ID made readable (`market_value` and `marketValue` both become "Market value").
- **kind** is the override's `kind`, else the input's `kind`, else `enum` when the override lists `enumValues`, else inferred from `sampleRows`. See [Column kinds](#column-kinds).
- **capabilities** is the override's `capabilities`, else the defaults, with `"aggregate"` added for a number, currency or percent column. A restricted column gets none.
- **sensitivity** is `restricted` for columns listed in `restricted`, `internal` for every other column. A restricted column is also marked `exposeToProvider: false`.

The result is checked against the `ViewSchema` shape before it is returned.

```ts
const schema = defineSchema(
  [{ id: "account_number" }, { id: "account_type" }, { id: "market_value" }, { id: "advisor" }, { id: "ssn" }],
  {
    id: "accounts",
    rowNoun: "account",
    restricted: ["ssn"],
    columns: {
      market_value: { kind: "currency", aliases: ["balance", "aum"] },
      account_type: {
        enumValues: [
          { id: "ira", label: "IRA" },
          { id: "roth_ira", label: "Roth IRA", aliases: ["roth"] },
          { id: "taxable", label: "Taxable" },
        ],
        valueGroups: [{ label: "Retirement", values: ["ira", "roth_ira"] }],
      },
    },
  },
);
```

## SchemaOptions

```ts
interface SchemaOptions {
  id?: string;
  version?: string;
  columns?: Record<string, ColumnOverride>;
  restricted?: string[];
  rowNoun?: string;
  defaultMeasure?: string;
  houseTerms?: HouseTerm[];
  calendar?: Calendar;
  sampleRows?: ReadonlyArray<Record<string, unknown>>;
}
```

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | `"default"` | The schema's ID. |
| `version` | `string` | `"1"` | The schema's version. |
| `columns` | `Record<string, ColumnOverride>` | none | Per-column additions, keyed by column ID: aliases, descriptions, approved enum values, narrower capabilities. |
| `restricted` | `string[]` | none | Column IDs GridCue must never expose to a provider or act on. |
| `rowNoun` | `string` | none | What one row is, such as `"account"`. Its name in a request means the rows, not a column. |
| `defaultMeasure` | `string` | none | The column a size word ranks by when the request names none: "top accounts", "largest to smallest", "smallest first" sort by it, descending for top, largest and biggest, ascending for smallest. It is also the column "largest households first" ranks groups by, when the grid shows totals: the question then offers "Rank households by total Market value" (or "by average" for a percent column) as a third choice. It must name a column; a restricted or unsortable one is never used. Without it, GridCue asks which column. |
| `houseTerms` | `HouseTerm[]` | none | Words your firm uses for a fixed set of conditions, such as "large" for Market value above $1,000,000. See [House Terms](#houseterms). |
| `calendar` | `Calendar` | none | The time zone and the first month of your year, which turn date words such as "last 90 days" into dates. See [calendar](#calendar). |
| `sampleRows` | `ReadonlyArray<Record<string, unknown>>` | none | Rows used only to infer missing kinds. They never leave the caller. |

## houseTerms

```ts
interface HouseTerm {
  label: string;
  aliases?: string[];
  where: Array<{ columnId: string; operator: FilterOperator; value?: Scalar | Scalar[] | { min: Scalar; max: Scalar } }>;
}
```

A **House Term** is a name you give to a fixed list of conditions on the rows. Each condition is a filter on a column by its id. Every condition must hold, so a term is its conditions joined by "and".

```ts
const schema = defineSchema(columns, {
  rowNoun: "account",
  houseTerms: [
    { label: "Large", aliases: ["big"], where: [{ columnId: "market_value", operator: "gt", value: 1_000_000 }] },
    {
      label: "Needs attention",
      aliases: ["need attention", "needing attention"],
      where: [
        { columnId: "concentration", operator: "gt", value: 0.1 },
        { columnId: "has_restricted_holding", operator: "eq", value: true },
      ],
    },
    { label: "Unassigned", aliases: ["orphaned"], where: [{ columnId: "advisor_name", operator: "isEmpty" }] },
  ],
});
```

A request that says a term as a whole word adds each of its conditions as a filter. "Large accounts" previews `Filter Market value above $1,000,000 (Large)`. The label in brackets names the term on every line it made, so the User sees the threshold and not only the word. Once applied, the view holds plain filters. See [House Terms in Requests](/docs/concepts/requests#house-terms) for what reads and what asks.

- **`label`** and **`aliases`** are the words that find the term. They match as whole words in any letter case, with any separator between their words: "needs-attention" finds "Needs attention". They have no plural form: "large" finds the term and "larger" does not.
- **`where`** holds at least one condition. `value` is a number, text, a yes/no, a list for `in`, or `{ min, max }` for `between`. An `isEmpty` or `isNotEmpty` condition has no value. An amount is a plain number: `1_000_000` for $1,000,000 and `0.1` for 10%.
- **A term holds no "or" and no moving date.** Each condition is a fixed filter. A request for either of two things asks, as it does without terms.
- **A term is never sent to an Intent Provider.** Not its name, its conditions, or whether a request matched one. `describeProviderPayload` leaves terms out.

`defineSchema` checks each condition the way validation checks a filter in a plan. The column must exist, not be restricted, allow `filter`, and allow the operator, and the value must fit the column's kind, so a `registration_type` condition must name one of its `enumValues` ids. It also checks that every name is the term's own. A label or alias throws when it is also:

- a column's label or alias, or the `entity` word of a column;
- a value's label or alias, or a Value Group's;
- the `rowNoun`;
- another term's label or alias;
- one of GridCue's own words, such as "top", "largest", "smallest", "empty", "blank", "show", "sort", "only" or "plus";
- only words a comparison is written with, such as "More", "Than", "Up", "Equal", "Valued" or "Worth": "gain more than $50k" and "accounts valued over $1m" would also keep the term's rows.

Plurals count as the same name, so a term named "Accounts" collides with `rowNoun: "account"`. A collision throws because the name would be read twice: "taxable" can't be both a value and a term.

A name also throws when it holds:

- one of GridCue's own words among its words: "Top tier", "Most valuable", "High value", "Reset pending" and "Due today" would also sort, reset or read a date. The small words GridCue places count too, so "Out of policy" throws; "Off-policy" doesn't;
- an amount or a count: "Tier 1", "1m", "Top 10";
- a name the schema already uses among its words: "Big gain" holds the alias "gain", "Northgate large" a value, and "Big accounts" the `rowNoun`. GridCue never looks for a term inside a declared name, so such a term could never be found.

A `between` condition throws when its `min` is above its `max`: it would keep no row.

## calendar

```ts
interface Calendar {
  timeZone?: string;
  fiscalYearStart?: number;
}

defineSchema(columns, { calendar: { timeZone: "America/New_York", fiscalYearStart: 1 } });
```

The Calendar turns date words in a request into fixed days, and says which day a cell is on. It holds those two fields and nothing else, and it is never sent to an Intent Provider. How requests use it is on [Requests](/docs/concepts/requests#dates).

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `timeZone` | `string` | The browser's time zone | An IANA name, such as `"America/New_York"` or `"Asia/Kolkata"`. Today, and the day a date-and-time cell is on, are worked out in it. |
| `fiscalYearStart` | `number` | `1` | The month your year starts in, 1 to 12. "This year", "last year" and "YTD" follow it, and quarters are counted in threes from it. With `4`, a year runs from April 1 to March 31, and on 2026-11-13 "this quarter" is 2026-10-01 to 2026-12-31. |

- **The default time zone is read late.** With no `timeZone`, GridCue reads the runtime's time zone when a request is read or a row is filtered, never when the schema is built: the browser's in a browser, and the machine's on a server. So a server that renders rows for Users in another zone filters by the server's days. Set `timeZone` when rows render on a server, or when your data is booked in one zone and Users sit in another. See [Going to production](/docs/guides/going-to-production#11-set-the-time-zone).
- **Leaving out `calendar`** is the same as `calendar: {}`: the browser's time zone and a year that starts in January.
- **Both Grid Adapters use it.** `applyView` reads it from the schema, and the TanStack Table adapter stores the time zone beside the column's kind, so both keep the same rows.
- **A bad value throws `INPUT_SCHEMA`** when the schema is built: a `timeZone` the runtime doesn't know, a `fiscalYearStart` that is not a whole number from 1 to 12, a field other than those two, or a `calendar` that is not an object.

## ColumnOverride

```ts
interface ColumnOverride {
  label?: string;
  kind?: ColumnKind;
  description?: string;
  aliases?: string[];
  capabilities?: ColumnCapability[];
  allowedOperators?: FilterOperator[];
  enumValues?: EnumValue[];
  entity?: string;
  valueGroups?: Array<{ label: string; aliases?: string[]; values: string[] }>;
}
```

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | input label, else humanized ID | The name Users and the provider see. |
| `kind` | `ColumnKind` | input kind, else inferred | The column's data kind. Declare `currency` and `percent`: they can't be inferred. |
| `description` | `string` | none | A short description sent to the provider. |
| `aliases` | `string[]` | none | Other names Users call this column, such as `["balance", "aum"]`. |
| `capabilities` | `ColumnCapability[]` | `DEFAULT_CAPABILITIES` | What GridCue may do with this column. Pass a narrower list to forbid, say, grouping. |
| `allowedOperators` | `FilterOperator[]` | the kind's operators | Narrows the filter operators. It can only remove operators the kind allows, never add one. |
| `enumValues` | `EnumValue[]` | none | The approved values, each `{ id, label, aliases? }`. Setting this without a `kind` makes the column an `enum`. |
| `entity` | `string` | none | The other record this column names, such as `"household"`, so "largest households first" can be read either as the column or as the records. |
| `valueGroups` | `Array<{ label, aliases?, values }>` | none | Host-named categories over the enum values, such as `{ label: "Retirement", values: ["ira", "roth_ira"] }`. Every value must be one of the column's `enumValues` IDs. |

## Column kinds

```ts
type ColumnKind = "string" | "number" | "currency" | "percent" | "date" | "datetime" | "boolean" | "enum";
```

Each kind has a fixed set of filter operators. `allowedOperators` can narrow it.

| Kind | Operators |
| --- | --- |
| `string` | `eq`, `neq`, `contains`, `startsWith`, `in`, `isEmpty`, `isNotEmpty` |
| `number` | `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `isEmpty`, `isNotEmpty` |
| `currency` | `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `isEmpty`, `isNotEmpty` |
| `percent` | `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `isEmpty`, `isNotEmpty` |
| `date` | `eq`, `gt`, `gte`, `lt`, `lte`, `between`, `isEmpty`, `isNotEmpty` |
| `datetime` | `eq`, `gt`, `gte`, `lt`, `lte`, `between`, `isEmpty`, `isNotEmpty` |
| `boolean` | `eq` |
| `enum` | `eq`, `neq`, `in`, `isEmpty`, `isNotEmpty` |

`operatorsFor(column)` returns the operators legal for a `ColumnDescriptor`: its kind's operators, narrowed by its `allowedOperators`.

### Operators and what a User can ask

Four of these operators are what GridCue's own code writes for the [text and empty forms](/docs/concepts/requests#text-forms-and-empty-values). Leave one out of a column's `allowedOperators` to turn its form off for that column. The request then asks instead of applying.

| Operator | Written for | Turned off, the request asks |
| --- | --- | --- |
| `startsWith` | `advisor starts with "Av"` | "GridCue can't filter Advisor by how it starts here." |
| `eq` | `advisor is exactly "Avery Lane"`, `advisor = "Avery Lane"` | "GridCue can't filter Advisor to exact text here." |
| `isEmpty` | `advisor is empty`, "accounts with no advisor" | "GridCue can't filter Advisor to rows where it is empty here." |
| `isNotEmpty` | `advisor is not empty`, "accounts that have an advisor" | "GridCue can't filter Advisor to rows where it is not empty here." |

`eq` and `startsWith` are written only for a `string` column. `advisor containing "Lane"` still works with any one of them turned off, since `contains` is a different operator. `isEmpty` and `isNotEmpty` are written for `string`, `enum`, `date` and `datetime` columns, never for `number`, `currency` or `percent`. A `boolean` column keeps its Yes or No reading. A form that GridCue can't write for a column's kind asks, whatever `allowedOperators` says.

### Kind inference

When no kind is given and the column has no `enumValues`, `inferKind` reads the column's values in `sampleRows`, ignoring `null`, `undefined` and `""`:

| All present values are | Kind |
| --- | --- |
| booleans | `boolean` |
| finite numbers | `number` |
| `Date` objects or strings starting `YYYY-MM-DDT` | `datetime` |
| strings of the form `YYYY-MM-DD` | `date` |
| anything else, or no values at all | `string` |

A money or percentage column infers as `number`. Declare it as `currency` or `percent` so amounts like "$1M" and "10%" reach it.

## Column capabilities

```ts
type ColumnCapability = "filter" | "sort" | "group" | "aggregate" | "show" | "hide" | "reorder" | "pin";

const DEFAULT_CAPABILITIES: ColumnCapability[] = ["filter", "sort", "group", "show", "hide", "reorder", "pin"];
```

Every column that is not restricted gets `DEFAULT_CAPABILITIES` unless its override says otherwise. `pin` is a default: a pin is a view change with no data risk. Pass a narrower `capabilities` list, one without `"pin"`, to keep a column from being pinned. A column's `pin` says whether the change is allowed; whether it shows depends on the grid. An adapter lists `columns.pin` only when the Host says its table draws pins, with [`renders`](/docs/api/adapters#renders).

`defineSchema` also adds `"aggregate"` to every number, currency and percent column that isn't restricted, so those columns may be totalled. `DEFAULT_CAPABILITIES` itself stays as listed above, because a total fits some kinds only. Whether a total fits is the kind's rule, checked apart from this capability: a sum fits a number or currency column, an average a number, currency or percent column, and a text, enum, date or yes/no column takes none (`PLAN_AGGREGATION_KIND`, see [Protocol](/docs/api/protocol#gridcueerror)). An adapter lists `aggregation.set` only when the Host says its table draws totals, with [`renders: ["totals"]`](/docs/api/adapters#renders).

A `capabilities` override replaces these defaults, as it always has. A Host that lists a column's capabilities by hand and leaves out `"aggregate"` keeps that column from being totalled: a request for its total asks "GridCue can't total Market value here." Add `"aggregate"` to the list to allow it. Before this change, no column could be totalled by default, so a Host upgrading finds that requests can now total columns it never opted in, once it sets `renders: ["totals"]`.

Density belongs to no column, so it has no capability.

## schemaFromTanStack

```ts
import { schemaFromTanStack } from "gridcue/tanstack-table";

function schemaFromTanStack(table: TanStackTableLike, options?: Omit<SchemaOptions, "sampleRows">): ViewSchema;
```

Builds a schema from a TanStack Table v9 instance. It reads every leaf column, uses a column's `columnDef.header` as its label when the header is a string, and infers kinds from the first 50 rows of the table's core row model. It takes every `SchemaOptions` field except `sampleRows`, which it fills itself, and passes them to `defineSchema`.

```ts
const schema = schemaFromTanStack(table, {
  rowNoun: "account",
  restricted: ["ssn"],
  columns: { market_value: { kind: "currency" } },
});
```

## describeProviderPayload

```ts
import { describeProviderPayload } from "gridcue";

function describeProviderPayload(schema: ViewSchema): {
  columns: ProviderPayloadColumn[];
  rowNoun?: string;
  rows: "never sent";
};

interface ProviderPayloadColumn {
  id: string;
  label: string;
  kind: ColumnKind;
  aliases?: string[];
  description?: string;
  enumValues?: EnumValue[];
  entity?: string;
  valueGroups?: Array<{ label: string; aliases?: string[]; values: string[] }>;
}
```

Returns exactly what an Intent Provider may receive about this schema, so you can review or log it. Restricted columns, and columns with `exposeToProvider: false`, are left out. Rows are never included; the `rows` field always reads `"never sent"`.

```ts
console.log(describeProviderPayload(schema));
```

## INPUT_SCHEMA errors

`defineSchema` (and so `schemaFromTanStack`) throws a `GridCueError` with code `INPUT_SCHEMA` when:

| Problem | Message |
| --- | --- |
| Two columns share an ID | `Column ids must be unique. Repeated: …` |
| `restricted` names an ID that matches no column | `restricted names an id that matches no column: …` |
| `columns` has a key that matches no column | `columns names an id that matches no column: …` |
| A `valueGroups` entry names a value that is not in the column's `enumValues` | `valueGroups on <id> name values that are not in its enumValues: …` |
| A House Term has no label, an empty alias, or no conditions | `House Term "<label>" has no conditions.` |
| A House Term's condition names an unknown or restricted column, or an operator or value the column doesn't allow | `House Term "<label>", condition 1: <problem>` |
| A House Term's label or alias is a name already in use, or one of GridCue's own words | `House Term "<label>": the name "<name>" is also a name of the column <label>.` or `… is one of GridCue's own words.` |
| A House Term's label or alias holds one of GridCue's own words, an amount, or a name already in use | `House Term "<label>": the name "<name>" holds “<word>”, one of GridCue's own words.`, `… holds an amount, which GridCue reads on its own.` or `… holds “<word>”, a name the schema already uses, so the term could never be found.` |
| A House Term's `between` condition starts above where it ends | `House Term "<label>", condition 1: its range starts at 5, above where it ends at 2, so it keeps no row.` |
| `calendar` is not an object, holds a field other than `timeZone` and `fiscalYearStart`, or has a bad value | `calendar.timeZone must be an IANA time zone name, such as America/New_York.`, `calendar.fiscalYearStart must be a month from 1 to 12.`, `calendar holds only timeZone and fiscalYearStart, not <field>.` or `calendar must be an object.` |
| The built schema fails the `ViewSchema` shape, such as an empty label or ID | `Invalid schema: <path>: <problem>` |

```ts
import { defineSchema, isGridCueError } from "gridcue";

try {
  defineSchema(columns, options);
} catch (error) {
  if (isGridCueError(error) && error.code === "INPUT_SCHEMA") console.error(error.message);
}
```

The full `ViewSchema` and `ColumnDescriptor` shapes are on the [Protocol](/docs/api/protocol#viewschema) page.
