# Changelog

## Unreleased

**AG Grid Community adapter** (ADR 0033)
- New entry `gridcue/ag-grid` exports `createAgGridAdapter`, `gridcueColumnDefs` and `schemaFromAgGrid`, with the types `AgGridAdapterOptions`, `AgGridApiLike`, `AgColDefLike`, `AgColGroupDefLike`, `AgColumnStateLike`, `GridcueColDef`, `GridcueFilterParams`, `GridcueFilterOption` and `GridcueTextMatcherParams`. It imports nothing from AG Grid and AG Grid is not a peer dependency. It is tested with AG Grid Community 34, 35 and 36, on the Client-Side and the Infinite Row Model. Enterprise is not tested.
- `gridcueColumnDefs(schema, columnDefs)` returns the grid's column definitions with the settings each schema column needs. It sets AG Grid's text, number and date filters to GridCue's meanings, lists on each column only the options GridCue reads there, takes an enum's label as its value, gives text a sort order of GridCue's, and sets a `cellDataType` on text, enum, number and yes/no columns that have none.
- The adapter lists the MVP operations without `group.set`, and no pins, density, totals or count. An apply writes the filter model and the column state, reads both back, and is done only when the grid holds them; a write the grid doesn't hold is put back and fails with `ADAPTER_FAILED`. A filter AG Grid can't hold fails with `ADAPTER_UNSUPPORTED_FILTER` before anything is written. A filter the User sets in AG Grid's menu is read into the View State. A filter GridCue can't read stays the Host's. `restore` refuses a view with a grouping other than the grid's; a count of `null` is no count.
- `createAgGridAdapter` throws `INPUT_CONFIG` for an api that is missing or lacks a call, a destroyed grid, a schema column that isn't a column of the grid, and a column the schema lets GridCue filter that has a `valueGetter` or `filterValueGetter`, or doesn't carry the settings `gridcueColumnDefs` gives it. `schemaFromAgGrid` gives a column with a `valueGetter` or `filterValueGetter` no `filter` capability.
- New guide, [AG Grid](https://gridcue.dev/docs/guides/ag-grid). The adapters page and [Rows on a server](https://gridcue.dev/docs/guides/rows-on-a-server) name it. New examples: `examples/ag-grid` (Vite) and an `/ag-grid` page in `examples/next`.

**Query Check for a Host's own Data Query** (ADR 0032)
- New entry `gridcue/testing` exports `queryCheck(schema, { id, operations?, notNull? })`, with the types `QueryCheck`, `QueryCheckCase` and `QueryCheckOptions`. It builds synthetic rows from your View Schema and a list of cases. Load `rows` into a test database, run each case's `state` through your own Data Query, and pass the ids it returns, in order, to `compare`. It imports no test runner and never reads or sends a real row.
- The cases cover the edges of each column and operator (empty cells, text case, accents in every text operator and padding, `%` and `_`, number ranges, date edges), then filters beside one another and on hidden columns, inside "or" groups too, an "or" group of three filters, an "or" group inside an "and" and an "and" group inside an "or", and the sorts: two columns at once, each number column by its value, each text and enum column on its own and as a second sort, each way, each sorted column beside a filter, each way and hidden, two sorts beside a filter, sorts on hidden columns, and long runs of tied rows for reading in pages. Text of letters alone is not all of one length, so text ordered by its length first fails. A count case appears only when `operations` lists `limit.set`, among them counts with two, three and four sorts that cut inside rows that tie on the sorts before the last, a count with text or an enum sorted second that cuts inside rows that tie on the first, a count sorted by text or an enum, a count that cuts inside tied rows beside a filter, a count sorted by a hidden column, and a count with an empty cell in each later sorted column.
- Pairs, and no more: each rule about sorting and counting sits beside each kind of filter, with the first sort each way. The rules are one sort, two sorts, and with `limit.set` the first rows of a count, a count that cuts inside tied rows, a count with two sorts that cuts inside rows that tie on the first, and a count of every row, which never keeps a row with no value in the first sorted column. The kinds of filter are one filter of each operator, one filter with a number, a date and a yes/no column sorted first, one filter on the first sorted column, two filters joined with "and", each "or" group, and each shape of a filter on a hidden column, with the sorted columns hidden too. A query that builds its sorts or its count another way under one such condition alone fails a case named for the rule it breaks. One that is wrong only where three such things meet can pass. Where a schema has no column that can show a rule beside a kind of filter, there is no such case.
- One column, and one number of sorts: with no filter, each column a case sorts by, text and enum columns too, leads two sorts, and three and four sorts are there with `limit.set` and without. With `limit.set` a count of every row is sorted by each column that holds empty cells, each way, a count cuts inside tied rows with one sort, two, three and four, and a count with text or an enum sorted first cuts inside rows that tie on it. A query that is wrong only for one column sorted first, or one number of sorts up to four, fails. Where text or an enum is sorted first, a row whose cell there has no checked place may sit anywhere among the rows that hold other text there.
- `compare` checks the ids as a set, and the order when the case sorts. An enum is ordered by its values' IDs, as text. Its message names the case, the missing ids and the extra ids, and for a count that returns the wrong number of rows, how many came back. Four things are yours. Text order is checked only between texts made of the letters A to Z that their letters tell apart: where a space, a digit, a mark or an accented letter sorts against a letter is your collation's own. Rows that tie on every sorted column may come in any order. A row with an empty sort cell is placed by its leading sorted columns that hold a value, and may sit anywhere among the rows that share them, so `NULLS FIRST` and `NULLS LAST` both pass. A count that cuts inside a run of tied rows may keep any of the tied rows for its last places: it must keep every row ahead of them, none behind them, every row the sorts put ahead of a row it keeps, and its number of rows in all, so `RANK` and `WITH TIES` fail with "18 rows came back, and the count asks for 14".
- Two cells of a sorted text or enum column that are the very same text tie on it, whatever characters they hold, so `compare` checks their rows by the sorts after it, in a count too. Two rows that both hold "Ålder Fen" or the enum ID `roth_ira` and come in the wrong order by the next sort fail with "wrong order". Texts that differ only in letter case, or in a space, a digit, a mark or an accent, still have no checked order between them.
- GridCue still never writes a Data Query. Nothing in the package builds SQL.
- New guide, [Rows on a server](https://gridcue.dev/docs/guides/rows-on-a-server), and API page, [Testing](https://gridcue.dev/docs/api/testing). The Next.js example gains a paged page with its own Data Query on `node:sqlite` (Host code), and a test that runs the Query Check against it.

**Query Adapter for rows the Host fetches** (ADR 0032)
- `createQueryAdapter` is for rows your own server fetches. It holds the View State and never fetches, and it never writes a Data Query. Build your Data Query from the View State each time it changes, and show your own loading and fetch errors.
- `countBeforePaging: true` lists `limit.set`, and only then. Set it when your server sorts, keeps the first N rows and then pages, and your Data Query keeps the rows `applyView` keeps for a count. Left out, "top 10 accounts by market value" ends as the sort with the note that the count was not applied, and "show only the first 5 rows" ends in the question "This grid can't show only the first 5 rows." and applies nothing.
- `without` takes out operations your Data Query can't carry out, such as `["group.set"]`. A request that asks for one ends in "This grid can't sort rows." (or the matching "can't" line for that operation) as a question with no choices, and nothing applies, not even the other parts of that request. A request that asks only for operations the grid lists works as it does on a default adapter. Your own Grid Adapter that leaves out one of these operations gets the same questions: before, such a request ended in "I'm not sure what to change for …" or in "This grid does not support sort.set."
- `renders` takes `"pinning"` and `"density"`, so the adapter lists `columns.pin` and `density.set` for what your table draws. `"totals"` and `"count"` throw `INPUT_CONFIG`: a total over rows on a server is a Data Query of its own.
- Its View State never holds a count without `countBeforePaging`, totals, pins without `"pinning"` or a density without `"density"`. An `initialState` or `setState` that holds one throws `INPUT_CONFIG`, and `restore` of such a snapshot, or `apply` of a plan whose view holds one, fails with `ADAPTER_NOT_APPLICABLE`. A count written as `null` is held as no count.
- Its subscribers work as the Rows Adapter's do. An error a subscriber throws comes out of the change that notified it, after the View State changed, so catch your fetch errors in the subscriber. A subscriber that calls `setState` as it is notified makes a newer change, which `apply` returns, and an Undo straight after takes it back too. Adjust the View State where you build the Data Query instead.

**Counts on TanStack Table** (operation set spec, 5.5; ADR 0027; ADR 0029)
- "Top 10 accounts by market value" and "show only the first 5 rows" now apply on a TanStack table, where they sorted and added the note "Count not applied: this grid can't show only the first 10". A Host that changes nothing sees nothing change: that note still shows on a TanStack table with no `"count"` in `renders`, and every request reads as before.
- `createTanStackAdapter` takes `"count"` in `renders`, and lists `limit.set` only then. The Host registers GridCue's count piece from `gridcue/tanstack-table`: `gridcueCountFeature`, which holds the count in the table's own store (`gridcueCount`, `onGridcueCountChange`, `table.setGridcueCount`), and `gridcueCountRowModel(createFilteredRowModel())`, which wraps the filtered row model and keeps the rows `applyView` keeps. The table sorts, groups and pages those rows as it does any others, and each group's total is over them.
- The table shows the same rows as `applyView`, in the same order, grouped and not, on every seeded view the shared rendered-rows test draws with a count (500 for each row set, plus views that differ only in the count). A row with no value in the first sorted column never fills the count, and rows that tie keep the Host's order. The differences between the adapters stay as they were, and none changes which rows a count keeps. A fifth one, older than counts, is now named and counted: a `null` beside a `0` in a sorted number column, where TanStack's basic sort can draw the rows that hold values out of order.
- `renders: ["count"]` throws `INPUT_CONFIG` on a table that holds one page of its rows (`manualPagination`, `manualSorting`, `manualFiltering` or `manualGrouping`), naming the setting, since the first rows of a page are not the first rows of the view, and on a table with `getSubRows`, since a count would keep each row with every one of its sub-rows. It also throws when the table's `filteredRowModel` is not `gridcueCountRowModel(…)`, when it has no `gridcueCountFeature`, on `useLegacyTable`, and when the adapter can't read the table's options. When the Host turns one of those settings on after the adapter is made, even before anything has read the table's rows, the count stops: the piece doesn't cut, the View State has no count, `limit.set` is not listed, a pending Preview is refused, and a write of a count fails with `ADAPTER_UNSUPPORTED_COUNT` and changes nothing.
- A count follows its rows on both adapters. After "top 10 accounts by market value", "sort by advisor" asks "Keep only the first 10 rows of the new view, or show every row?" on TanStack Table as on the Rows Adapter. Undo and restoring a snapshot keep the count, and a sort the User makes with the table's own header is reported like any manual change, with the count then keeping the first rows of the new order.
- `rowsBeforeCount(table)` gives the rows the table's filters leave, before the count, for a caption such as "First 10 of 48 rows". `countOrder(positions, cell, sorts)` is exported from `gridcue`: the choice of rows a count makes, for an adapter that keeps a count in its own table. `applyView` uses it too.
- A count drops the rows with `NaN` in the first sorted column before it sorts them, on both adapters. Before, a `NaN` cell broke the sort's order, so a count of 1 on the values 3, `NaN` and 1, sorted ascending, kept 3. A view with no count sorts as before.
- The request a provider receives is the same for every labelled request. The resolution protocol stays at 0.1, and `gridcue/react`, `gridcue/server` and `gridcue/mock` don't change.

**Totals, and one group order** (operation set spec, 4.3 to 4.5, 5.2 and 5.4; ADR 0028; ADR 0029; ADR 0030)
- Three changes to old behaviour, the first of which reaches Hosts that change nothing. **1. The Rows Adapter's group order.** `applyView` used to group the sorted rows, so a descending sort on Market value put first the group that held the largest single row. It now orders the groups of a grouped, sorted view as TanStack Table does: by the total, when the sort is on a column with a total; by the column's value, when it is on a grouping column; otherwise in the order the groups first appear in the rows the view shows. Rows inside each group are still sorted. A grouped, sorted view that requests reach today can draw its groups in a different order with the same View State, in the Rows Adapter only (the Next.js example). A Host that read the old order as a ranking can ask for one with a total: "total market value by advisor", then "sort by market value, descending". **2. The Preview's totals wording.** `aggregation.set` read "Summarize Market value (sum)". It now reads "Show the total of Market value", "Show the average of Concentration", "Show the average of Market value instead of its total" and "Remove the totals". **3. `defineSchema` adds `"aggregate"`** to every number, currency and percent column that isn't restricted, unless its `capabilities` override says otherwise. `DEFAULT_CAPABILITIES` is unchanged. A total still reaches a grid only through `renders`, so a Host that doesn't set `renders` gets no total, and a Host that does finds requests can now total columns it never opted in. A `capabilities` list a Host wrote by hand replaces the default, so leave `"aggregate"` out of it to keep a column from being totalled.
- A request can show totals. GridCue reads a closed list of words with its own code, which the provider never decides. "Total market value", "sum of market value", "show the total of market value" and "show total market value" show a sum; "average concentration" and "show the average of concentration" an average; "total market value by advisor", "sum of market value by advisor" and "average concentration by custodian" also group by the second column, replacing the grouping as "group by" does, though never a grouping the same request said first, even one the view already had ("total market value by advisor and total unrealized gain by custodian" asks); and "remove the totals", "clear the totals" and "no totals" clear them. "Also" may come before a form. "Per", "mean", "avg", "X totals", "how much does each advisor manage" and "hide the totals" are not read, and ask as before.
- A total is added to the view's totals, and the plan's `aggregation.set` carries the whole list, so a total on another column never goes unless a request removes it. A column holds one total at a time: "average market value" on a view that shows its total replaces it, and the Preview says "instead of its total". A request that names a column's total twice, or hides a column and totals it too, asks.
- A total that doesn't fit its column's kind is not valid. A sum fits a number or currency column, and an average also a percent column. "Total concentration" asks "Concentration can't be totalled. Show its average instead?" with Yes and No, "total concentration and total yield" names both ("Concentration and Yield can't be totalled. Show their averages instead?"), and "total registration type" says "Registration type can't be totalled.", as does a part that totals such a column beside a percent one. Validation says the same with `PLAN_AGGREGATION_KIND`, and two totals on one column fail with `PLAN_INCONSISTENT_STATE`. `ViewCapabilities` gains `aggregationFunctions`, the functions the grid applies, which defaults to a sum and an average: a plan with a minimum, a maximum or a count fails with `PLAN_AGGREGATION_KIND`, and no request produces them.
- A total counts the rows the view shows, after its filters and its count. Empty values are skipped, an average is the sum over the rows that have a value, and a group or a view with no values has an empty total (`null`), never 0. A sum is exact in decimal, so cents don't drift (`0.1 + 0.2` is `0.3`) and the total doesn't depend on the order of the rows. An average is that exact sum divided once by the count. `totalOf(values, "sum" | "avg")` is that arithmetic, exported from the root for custom adapters.
- A totals form is read as a whole part, or at the end of one after "and" or a comma ("group by advisor and total market value"). After a sort, or a list of columns to hide or show, it asks, since the words may be one more item of that list ("sort by gain and average concentration"). After a clear that names what it removes, it asks too, since the clear may take it ("remove the totals and total market value", "clear the sort and total market value"); a total with its own verb ("remove the totals and show the total of market value") is read. A totals word no form read ("total", "totals", "sum", "average", and the like) never leaves a ready Preview on a grid that lists totals: "northgate accounts total" and "sort by total market value" ask about that word. A name the Host declared keeps its words ("Total return", an "Average cost" column, "average cost by holder"), quoted text keeps its own, and "average" right after "above", "below", "over", "under" or "than", or "above-average", is a level to compare with and not a totals word. A name made only of totals words ("total" or "sum" as an alias) asks on a grid that lists totals, where the request shows totals or its part groups ("group by owner with totals"), or wherever another column a total fits is named right after it ("sort by total units"). A request with none of these words reads as before.
- A total on a column the view groups by asks: "GridCue can't group by Unrealized gain and show its total too." A group row shows its own value there. Validation refuses the same view with `PLAN_INCONSISTENT_STATE` for a plan that groups or sets totals.
- `createRowsAdapter` and `createTanStackAdapter` take `"totals"` in `renders`, and list `aggregation.set` only then. Without it, a request for a total, the grouping of "total X by Y" included, ends in "This grid can't show totals." with no choices and nothing applied, and a request with none of these words reads as before.
- `applyView` returns `totals` (one `{ columnId, function, value }` for each total, over every row the view shows) and a `totals` for each group.
- `gridcueAggregationFn` and `gridcueAggregationValue` from `gridcue/tanstack-table` let a TanStack table draw the totals GridCue holds. Register both on `defaultColumn`, with `rowAggregationFeature`. A group row's `getValue(columnId)` is its total, so a sort on that column orders the groups by it, and `column.getAggregationValue()` is the footer's. The adapter holds the totals, reads them back with the rest of the View State, so undo puts them back, and regroups when they change so each group row reads the new total. On a grouped view a totals change is done only once the table has grouped again: a Host that hands the table back the grouping array it had gets "The grid couldn't apply that change. Nothing was changed." rather than group rows with the old totals. Over the same rows they give the numbers `applyView` gives, to the last digit. The groups can differ: TanStack Table puts `null` and missing cells of a grouped column in two groups where `applyView` puts them in one, so those groups' totals differ; the adapter guide lists this and the older differences in sorting. `createTanStackAdapter` throws `INPUT_CONFIG` for `"totals"` when it sees no `rowAggregationFeature`, a column the schema lets it total that the table lacks, or a column that doesn't use the two functions.
- "Largest households first" gains a third choice where the grid shows totals and the schema declares a `defaultMeasure`: "Rank households by total Market value" (an average for a percent column). "Most concentrated households first" offers "Rank households by average Concentration": a ranking word after "most" or "least" that is a column's name with "-ion" written "-ed" names that column. It applies the grouping, the total and a sort on the total's column, descending ("smallest": ascending), and the Preview shows all three lines. `defaultMeasure` already stood in for the column a size word names, and now also picks the column a group ranking totals. With no column to rank by, on a grid that doesn't show totals, or where the grid may not group by Household, the question keeps its two choices.
- `ViewDiff` gains `totalsChanged`, and the audit's structure lists the columns of `aggregation.set`, never a value.
- The request a provider receives is the same for every labelled request. The resolution protocol stays at 0.1, and `gridcue/react`, `gridcue/server` and `gridcue/mock` don't change.

**Pins and density** (operation set spec, 5.2 and 5.3; ADR 0028; ADR 0029)
- A request can pin and unpin columns and set the density. GridCue reads a closed list of words with its own code, which the provider never decides. "Pin account number" and "pin advisor and household" pin to the start; "pin the advisor column", "pin market value to the right" (or "to the end"), "pin advisor to the left" and "freeze the advisor column" work too; "unpin advisor", "unpin all columns", "unpin all" and "unpin everything" unpin; "compact view", "spacious rows", "comfortable mode" and "use compact density" set the density. The Preview says "Pin Account number to the start", "Pin Market value to the end", "Unpin Advisor", "Unpin all columns" and "Use compact density". All of these asked "I'm not sure what to change…" before. A form is read only when every word is a form word, a column the grid names, or a filler: "freeze advisor" with no "column", "lock advisor", "pin advisor to my watchlist", "pin the Northgate accounts", "make it denser", "tighter" and "compact exceptions view" still go to the provider and ask. "Left" and "right" mean the start and the end, which assumes a grid that reads left to right.
- A pin or a density can be said after "and" or a comma at the end of a part: "group by advisor and pin advisor" previews "Group by Advisor" and "Pin Advisor to the start". `Advisor starts with "Av", pin advisor` asked about “pin” before, and is now ready where the grid draws pins.
- Columns come only from the names the Host declared. "Pin the account column" asks when "account" is the `rowNoun` ("GridCue can't tell whether “account” means the Account number column or the rows. To pin the column, say “pin the Account number column”."), and so does a yes/no column's name without "column" after it ("pin restricted"). A name that holds a form word, such as a size class "Compact", asks wherever the words sit: "“compact” is a name in this grid, so GridCue can't tell what “compact view” asks for." "Compact view sorted by mileage" and "midsize vehicles compact view" filtered by the size class before. After a word that takes the rows ("hide the compact rows"), "compact rows" still says which rows. On a grid that doesn't draw the density, such words can only be the Host's name, and they read as before. A restricted column is refused, as before.
- A pin or density word said where no form reads it never leaves a ready Preview without it. Before, a part was read only as a whole or at its end, so "compact view, top 10 by market value", "taxable accounts in compact view", "pin market value above 1m" and "group by advisor with advisor pinned" previewed the other change alone, as they did before this release. Now a form said there asks, "GridCue can't tell how “compact view” fits with the rest of that part. Try asking for it on its own.", and a pin or density word no form reads asks about that word. Inside quoted text, a declared name, a House Term or a Local Value the word is the name's, unless a declared name starts a form there (above), and "the pins stay" asks for nothing.
- Pinning a hidden column previews "Show Concentration" and "Pin Concentration to the start". A column is pinned once: the reducer removes it from both lists before it adds it, so pinning it to the other side moves it. A request names only the columns it changes: "pin advisor" with Advisor already pinned to that side keeps it where it is, and an unpin leaves a column that isn't pinned alone. When nothing would change, as "unpin everything" with nothing pinned, GridCue says "The grid already shows this view." An unpin that names every pinned column previews "Unpin all columns". "Unpin everything" never names a restricted column the Host pinned. Hidden, it stays pinned and the others are unpinned; shown, GridCue asks "GridCue can't unpin every column here. To unpin the others, name them."
- A House Term may not be named with a word a pin or density form reads ("Unpin", "Freeze", "Start", "End", "Left", "Right", "Mode", "Density", "Use"): `defineSchema` throws `INPUT_SCHEMA`, as it does for GridCue's other words.
- `createRowsAdapter` and `createTanStackAdapter` take `renders`, a list of what the Host's table draws: `"pinning"` and `"density"`. An adapter lists `columns.pin` and `density.set` only for what it names. The default is none, so adapters list what they listed before, and a request to pin, unpin or change density asks "This grid can't pin columns." or "This grid can't change its density." with no choices and nothing applied, the other parts of the request included. It is the same question as "This grid can't group rows.", and not an Unsupported Segment. GridCue can't check what a table draws, so a Host that names something it doesn't draw gets a Preview and "View updated." with nothing to see. Any other name, and a `renders` that is not a list, throws `INPUT_CONFIG`, as do `"count"` on the Rows Adapter and `"totals"` and `"count"` on the TanStack Table adapter, which don't take them yet. The TanStack Table adapter also throws `INPUT_CONFIG` for `"pinning"` when the table has no `setColumnPinning` (register `columnPinningFeature`), or holds its pins as `left` and `right`, as TanStack Table v8 did, where v9 reads `start` and `end`.
- `DEFAULT_CAPABILITIES` gains `"pin"`: every column that isn't restricted may be pinned unless its `capabilities` override leaves it out. This is the column gate. A pin reaches a grid only through `renders`, the grid gate, so a Host that doesn't set `renders` gets no pin. On such a grid, any pin or density form in a request asks "This grid can't …", wherever it is said and whichever column it names ("compact view of taxable accounts", "pin restricted"); a request with a part outside the view ("pin advisor and export the list") is refused for that part instead. A Host that does set `renders` finds that requests can now pin columns it never opted in; pass `capabilities` without `"pin"` to keep one out.
- `ViewResult` from `applyView` gains `pinned` (`{ start, end }`, the visible pinned columns, each in pin order) and `density`. `columns` puts the start-pinned columns first and the end-pinned columns last. A hidden pinned column is in neither list, keeps its pin, and is pinned again when shown. They hold the View State whether or not the adapter lists the operations.
- The TanStack Table adapter reads and writes pins through TanStack's own `columnPinning` state, only when `"pinning"` is named, and a pin the User makes with the table's controls is reported as a change. TanStack has no density, so the adapter holds it, reads it back with the rest of the View State, and undo puts it back. `TanStackTableLike` gains an optional `setColumnPinning` and `TanStackState` a `columnPinning`.
- `ViewDiff` gains `pinsChanged` and `densityChanged`. `renderPreview` takes the current view's `pinnedColumnIds` to say "Unpin all columns".
- The adapter contract suite replaces "doesn't advertise `columns.pin`, `aggregation.set`, or `density.set`" with "lists each only when `renders` names it". For every operation an adapter lists beyond the first-release ones, and for `limit.set`, it applies, reads back, restores an exact snapshot, undoes and counts one notification per write. Both adapters run it with and without `renders`.
- The request a provider receives is the same for every labelled request, and a request with none of these words reads as before. The resolution protocol stays at 0.1, and `gridcue/react`, `gridcue/server` and `gridcue/mock` don't change.

**Dates** (named filters spec, 5.5; ADR 0026)
- A request can say a date in words. "Entries booked in the last 90 days" filters Booked from 2026-08-15 to 2026-11-13, on 2026-11-13. GridCue reads these forms with its own code, and the provider never decides which days they mean: "today", "yesterday"; "last 90 days" and "past 90 days", also with weeks, months and years (a whole number from 1 to 999, a week is 7 days, and a month day that doesn't exist is that month's last day); "this month", "this quarter", "this year"; "last month", "last quarter", "last year", the whole period before this one; "month to date", "quarter to date", "year to date", "MTD", "QTD", "YTD"; a range of two ISO dates ("between 2026-01-01 and 2026-03-31", "from A to B", "from A through B", both ends included, swapped when written high to low); and one ISO date with a comparison, as before. A form may follow "in", "in the", "over the", "during", "during the", "within the" or "for the". Added: `SchemaOptions.calendar`, `ViewSchema.calendar` and the `Calendar` type, `GridCueOptions.now`, the error code `INPUT_CLOCK`, `normalize(text, { today, calendar })` and `NormalizeOptions`, `Literal.words` (core only, never sent to a provider), and `matchesPredicate(value, predicate, column, { timeZone })` with the `MatchOptions` type. Nothing is removed or renamed.
- A relative date is worked out once, when the request is made, and the view keeps the two days as an ordinary `between` filter. The protocol, the View State and the Grid Adapter interface don't change, and a view applied today shows the same dates next month. The Preview keeps the User's words in the plan's evidence, not in the view.
- The Calendar holds `timeZone` and `fiscalYearStart`, and nothing else: `defineSchema(columns, { calendar: { timeZone: "America/New_York", fiscalYearStart: 1 } })`. `timeZone` is an IANA name. Left out, it is the runtime's, read when a request is read or a row is filtered, never when the schema is built. `fiscalYearStart` is a month from 1 to 12, default 1, and years, quarters and the "to date" forms follow it. A bad name, a month outside 1 to 12, another field or a `calendar` that is not an object throws `INPUT_SCHEMA`. The Calendar is never sent to an Intent Provider.
- `now` returns the current time and defaults to the system clock. It is called once for a request, and only when the request holds a relative form. A `now` that throws, or returns anything but a valid `Date`, stops the request with `INPUT_CLOCK` and "Couldn't read today's date. The view hasn't changed." The provider is not called and the view doesn't change. A `now` that cancels the request, or makes a newer one, leaves that state as it is, and the provider is not called for the cancelled request. Day arithmetic is done on calendar days, never by adding hours, so a clock change can't move a date.
- The date goes to the date column named right before the form: "entries booked in the last 90 days". That now also holds right after the grid's `rowNoun` or a value, where the name was lost: "fees entries booked this quarter" filters Category to Fees and Booked to the quarter. With no date column named, the provider's confident pick of a date column decides, or GridCue asks "Which date column should “last 90 days” filter?". A grid with no date column says "This grid has no date column for “last 90 days”."
- Every time word of these kinds asks and is never dropped: "this week" and "last week" (the Calendar holds no first day of the week), a comparison before a relative form ("before this quarter", "since last month"), "90 days ago", "next month", "recently", a month name ("since january", "May 2026"), a slash date ("1/31/2026"), a quarter or half by number or place ("Q1", "3Q", "H1", "1st half", "back half"), a fiscal year ("fy", "fiscal", "FY2025"), a weekday or a unit written short ("mon", "qtr", "mo", "yday", "2wk", "90d"), a unit with a prefix ("semiannual", "biweekly"), a period written short ("ttm", "ltm", "cob"), "period" itself ("this period", "prior period"), a unit joined to where in it ("midyear", "yearend"), a day of the month ("on the 15th", "on the fifteenth"), a decade ("the 90s", "the nineties"), up to now ("to date", "so far", "as of now", "til now", "in the past"), a time of day ("this morning", "noon", "9am", "9:30"), the end of a period ("eod", "eom", "close of business"), a season or a holiday ("summer", "xmas"), and a number outside 1 to 999. So does "this", "last", "prior", "previous", "past", "since" or "until" right after the rows or a date column (the `rowNoun`, a value or a date column's name, with "in", "for", "during" or the like between) and right before a word GridCue doesn't read, which names a period it has no form for or a time word written wrong ("travel entries this season", "last cycle", "last quater", "since inception", "since the start", "entries booked last cycle"). Each kind is found written with a space, a hyphen or dots ("back-half", "to-date", "t.t.m."). A word GridCue reads for the view after it is no period ("this view", "the last column"), and beside a code-read filter such a word asks as an unplaced word, as before. A place in the grid and a share are not time words: "put advisor last", "the next column", "the 2nd column" and "a quarter of the entries" read as before. A word of none of these kinds ("soon", "earlier", "first thing") is not read as a time word, and in a part with no code-read filter it is still dropped, as any word nothing reads is. Inside a declared name or a Local Value, a time word is the name's: "sort by last month return" sorts by the column Last month return, and "Today Partners" is the value. A form's days that would fall outside the years 0001 to 9999 make it no form, so it asks too. The question is "I'm not sure which dates “this week” means. Use dates like 2026-01-31, or “last 90 days”." Before, "taxable accounts since january" filtered Taxable and dropped the date, and "accounts opened in the last 90 days" asked how to compare with “90”.
- A dictated "period" still ends a sentence ("show taxable accounts period sort by value"), but no longer after a word that makes a span of time of it: "this period", "last period", "prior period", "current period", "the period", "the reporting period". Those reach the reader as written, and ask as time words. Before, "travel entries last period" filtered Travel and dropped the rest.
- A range of two dates with a comparison after it is no range: "booked from 2026-01-01 to 2026-03-01 or later" asks, as it did before dates were read. "Or so" after a form or any other code-read filter is never dropped: "booked last month or so" asks "I'm not sure what to do with “or so”. Try rephrasing that part." One date with "or later" is still on or after it.
- A date form is a code-read filter, so the rules of the text forms, House Terms and Local Values hold for a part with one: every word must be placed, a statement asks, a column asked for beside the form must end up in the plan, and a provider's picks are limited to what the words name. "Entries booked in the last 90 days called about travel" asks about “called about”. A date with no column named never takes a date column the part names, for another date or any other change: "entries in the last 90 days booked this quarter" asks which date column “last 90 days” filters. The provider's pick of a date column goes to that date alone, never to a sort or a grouping no word names. A request with no time word, no date and no date column reads as before, with a calendar set or without. The request a provider receives is the same with any clock and Calendar: a relative form reaches it as a plain number, and the payload pin test passes with its lines unchanged.
- A date in a filter means the whole day in the Calendar's time zone, on date and date-and-time columns alike. A cell is first turned into its day: a date string is that day; a `Date`, or a string with a time and an offset, is the day that instant falls on in the zone; a string with a time and no offset is its own date part. A cell that can't be read as a date matches no date filter. This changes old behaviour too: a date filter compared cells as they were, so a column of epoch numbers or "11/13/2026" text matched a filter written the same way, the Host's own View State included. Now such a cell matches no filter on a `date` or `datetime` column. Turn each cell into an ISO date, an ISO date and time, or a `Date` before the rows reach the grid, or declare the column as `number` or `string`. A filter value that holds a time is compared as an instant. `applyView` and `matchesFilter` read the zone from the schema, and the TanStack Table adapter stores it beside the column's kind, so `gridcueFilterFn` keeps the same rows. Before, dates were compared as text, so "after 2026-01-31" on a date-and-time column kept a row stamped on the 31st. Set `timeZone` when rows are filtered on a server, or when the data is booked in one zone and Users sit in another.
- Two changes to old behaviour. The Preview's words for a date filter: "Filter Booked after 2026-01-31", "on or after", "before", "on or before", "on", and "from … to …", with no quote marks, where it said "above “2026-01-31”", "at or below “2026-01-31”" and "to “2026-01-31”". The line for a relative form ends with the words in brackets: "Filter Booked from 2026-08-15 to 2026-11-13 (last 90 days)". On a date-and-time column the Preview adds one note, "Whole days, in America/New_York time". And the question for a date on a date-and-time column, "Posted at holds times of day, so GridCue can't filter it by date yet.", is removed: "posted after 2026-01-31" is a ready Preview now, since a date means the whole day.

**Local Values** (named filters spec, 5.4; ADR 0025)
- A request can name a value the grid's rows hold. `createGridCue({ adapter, provider, localValues: { advisor_name: () => rows.map((row) => row.advisor_name) } })` makes "Avery Lane's accounts", "accounts for Avery Lane" and "advisor is Avery Lane" filter Advisor to exactly “Avery Lane”, in the grid's own letter case. "Avery Lane or Blake Moreno" makes one filter that keeps either. Added: `GridCueOptions.localValues`, the `LocalValues` type, the error code `INPUT_LOCAL_VALUES`, and `localValuesFromTable(table, columnIds)` in `gridcue/tanstack-table`. Nothing is removed or renamed. Off unless set: with no `localValues`, every request reads as before.
- A Local Value is read in the browser, by GridCue's own code, and is never sent to an Intent Provider. The request is built before any value is looked at, so it is the same with `localValues` on or off, and the provider is called once whether or not a value matched. A name the User types is in the request, as any word is. The Preview shows the value as the grid holds it: "Filter Advisor to exactly “Avery Lane”", and "Filter Advisor to any of “Avery Lane” and “Blake Moreno”" for a list. A value is in the plan, the Preview, a question and the view's filter, and in an audit event only as the User's own request text when `includeText` is on.
- `localValues` is a function for each text column the Host names. A column must be a text column that is exposed, not restricted, allows `filter`, and has `eq` and `in` among its operators when it sets `allowedOperators`, or `createGridCue` throws `INPUT_CONFIG`, as it does for a key that is not a column, a value that is not a function and a `localValues` that is not a plain object (a `Map` included). The function is synchronous. GridCue drops values that are not text, hold no letter or digit, or repeat an earlier value in any letter case, builds a word index, and keeps it while the function returns the same array. A function that throws, or returns something that is not an array, stops the request with `INPUT_LOCAL_VALUES` and "Couldn't read this grid's values. The view hasn't changed." The provider is not called and the view doesn't change. A function that cancels the request, or makes a newer one, leaves that state as it is, and the provider is not called for the cancelled request. For a grid that pages, the Host passes its own list of every name, not the page.
- `localValuesFromTable(table, ["advisor_name", "household"])` reads every loaded row of a TanStack table, sub-rows included, whatever filters the table has, so a name is found while the User's filter hides its row. It returns the same array while the table's data is the same array. A column id the table doesn't have throws `INPUT_CONFIG`. `TanStackTableLike.getCoreRowModel()` may now hold `flatRows`.
- A whole value is read as every word of it, in order, as whole words, in any letter case. Between two of its words the request may hold spaces, one hyphen, underscore, full stop or apostrophe with no space beside it, or the punctuation the value itself holds there; any other punctuation separates two names. There is no plural. The longest name wins: "the Alder household" is the value Alder Household, not the Household column. A number inside a value ("Fund 7") is part of its name. Quoted text is never read. A value made only of GridCue's own words ("Top 10") is never read from the grid.
- A Local Value is a code-read filter, so the rules of the text forms and House Terms hold for a part with one: every word must be placed, a statement asks, a column asked for beside the value must end up in the plan, a provider's picks are limited to what the words name, and a yes/no column named on its own keeps Yes. "Avery Lane called about the trust accounts" asks about “called about”. "Show taxable accounts for Avery Lane" adds both filters. "Group by advisor for Avery Lane" filters and groups. Before, each of these asked or dropped the name. A value's own words never say to keep the view's filters: "show Further Lane" replaces them, as "show Avery Lane" does.
- These ask: a value left out ("hide Avery Lane", "everyone except Avery Lane": "GridCue can't leave out “avery lane” yet. Ask for the rows to keep."), a value where a column goes ("sort by Avery Lane": "Avery Lane is a value in Advisor, not a column."), a statement ("Avery Lane is an advisor"), a possessive that owns something other than the rows ("Avery Lane's household"), two values of one column apart, or each after the column's name with anything but "or" between them ("Avery Lane's accounts for Blake Moreno", "advisor is Avery Lane and advisor is Blake Moreno": "No row has two Advisor values. Ask for them as one list, such as “Avery Lane or Blake Moreno”."), values of two columns with "and", "also", a comma or a dash anywhere between them, each with the rows' own noun, or in two parts ("Avery Lane and the Alder household", "Avery Lane's accounts and the Alder household's accounts", "Avery Lane's accounts the Alder household's accounts", "Avery Lane's accounts; the Alder household"; two values that each follow their column's name are read as two conditions: "advisor is Avery Lane and household is Alder Household"), a value beside another filter on its column that no row can match with it ("Avery Lane's accounts with no advisor": "No row matches every Advisor filter, so the view would be empty. Ask for the rows to keep."), and a word built on "group" that is a word of a value, where the part doesn't group ("entries in the Travel Group", on a grid that holds Hollis Travel Group). "Accounts held by Avery Lane" asks about “by”, which is placed only beside a sort or a group. "Avery Lane's accounts in the Alder household" and "Avery Lane's Alder household accounts" add both filters.
- Which value was meant asks one question at a time, and the answer stays in the browser. A value two columns hold, or that is also a declared name (a column, a value, a Value Group, the `rowNoun`, an entity word or a House Term), asks "Which did you mean by “dunmore”?" with each value, and each column's declared names, as a choice. A question offers five choices at most, then "None of these"; with more it has no choices and asks the User to rephrase. One word of a value asks: "Lane's accounts" asks "Did you mean Advisor: Avery Lane?" with “Yes, Avery Lane” and “No”. Two to five values ask "Which Advisor did you mean by “lee”?" with each value and "None of these". Six or more ask "6 Advisor values contain “lee”. Type the full name." with no choices. A word that is a declared name or one of GridCue's own words is never offered. A value picked from a question is read at its own words, so the question's words it leaves out are still placed or asked about. "None of these" says nothing will change: "Nothing will change for “lane”. Type the full name, or rephrase that part."
- `describeProviderPayload` leaves Local Values out. The payload pin test passes with its lines unchanged, with `localValues` on and off.
- A choice with a long name wraps inside the bar. A question's choices can now be values the grid holds, and a long one was wider than a narrow bar: at 320 px the page scrolled sideways. In `<GridCueBar />` a choice has the new class `gridcue-choice`, and the bar's one grid column may be narrower than its content, so the input row shrinks too. In the Component Registry's `clarification-prompt`, a choice keeps its 32 px height on one line and grows when it wraps.

**House Terms** (named filters spec, 5.3; ADR 0024)
- A Host can name a filter. `defineSchema(columns, { houseTerms: [{ label: "Large", aliases: ["big"], where: [{ columnId: "market_value", operator: "gt", value: 1_000_000 }] }] })` makes "large accounts" and "show the big accounts" filter Market value above $1,000,000. A term holds one or more conditions, and every one must hold: "accounts that need attention" with Needs attention declared as Concentration above 10% and Restricted holdings is Yes adds both filters. Added: `SchemaOptions.houseTerms`, `ViewSchema.houseTerms` and the `HouseTerm` type. Nothing is removed or renamed.
- A term is found as a whole word, in any letter case, by its label or an alias, with no plural form. "Large" is the term and "largest" and "larger" are not. "Largest accounts" is still a size word and still asks which column to sort by when the grid declares no `defaultMeasure`.
- The Preview names the term in brackets on each line it made: "Filter Market value above $1,000,000 (Large)", "Show only rows where Advisor is empty (Unassigned)". The view keeps plain filters. The label is in the plan's evidence, with source `host`, also when the User typed an alias.
- `defineSchema` checks each condition the way validation checks a filter in a plan: the column exists, is not restricted, allows `filter` and the operator, and the value fits its kind. A bad one throws `INPUT_SCHEMA` and names the term and the condition. It also throws when a label or alias is a column's, a value's, a Value Group's, the `rowNoun`, an `entity` word, another term's, or one of GridCue's own words such as "top", "largest", "smallest", "show" or "empty". Plurals count as the same name. A name that holds such a word throws too, since GridCue would read that word as well: "Top tier", "Most valuable", "High value", "Out of policy" and "Due today". GridCue's own time words are the units its date forms are made of ("today", "days", "quarter", "YTD"), and "tomorrow", "ago", "next", "recent" and the month names; "May" counts only where a number could follow it, so "May items" is a name and "May" is not. So does a name that holds an amount or a count ("Tier 1", "1m", "Top 10"), a name that holds a column's or a value's name, the `rowNoun` or an `entity` word, since such a term could never be found ("Big gain", "Northgate large", "Big accounts"), a name made only of words a comparison is written with ("More", "Than", "Up", "Equal", "Valued", "Worth"), which "gain more than $50k" would also find, and a `between` condition whose low end is above its high end.
- A term is a code-read filter, so the rules of the text and empty forms hold for a part with one: every word must be placed, so a question word asks ("who is large"), a column asked for beside the term must end up in the plan, and a provider's picks are limited to what the words name. "Large accounts called about retirement" asks about “called about”. "Large accounts sorted by size" asks about “size”.
- A term left out asks: "accounts that aren't large" and "hide large accounts" ask "GridCue can't leave out “large” yet. Ask for the rows to keep, such as “market value at or below $1,000,000”." A term where a column goes asks: "sort by large" asks "“large” stands for rows, not a column. Name a column instead, such as Market value." "Large or taxable accounts" asks for one condition at a time, as either-or does without terms. A term holds no "or" and no moving date.
- A term where an amount goes asks: "accounts under large" asks "I'm not sure what to do with “under large”. Try rephrasing that part." Before, it kept the accounts above $1,000,000, the opposite of what was asked. So do "larger than big", a preposition with nothing after the term ("accounts at large"), and a term right after an amount ("gain 50k large"). A term that describes the owner of the rows asks: "large households' accounts" asks about “large households'”. The rows right before a term ask when the term is no "-ing" or "-ed" word, since they say something of the rows: "accounts need attention" asks, and "accounts needing attention" and "accounts unassigned" are read. With other words between, the rows ask before a term said as a verb, one of several words whose first ends in a verb's "s" ("needs attention", "breaches limit") or whose names include the same words with and without that "s": "Northgate needs attention", "these accounts at Northgate need attention" and "trusts need attention" ask, and "accounts at Northgate large" is read. With terms declared, "accounts larger than taxable" asks about “larger”: no amount follows it.
- In a part with a text form, an empty form or a term, a yes/no column named on its own keeps Yes. A provider's No for it is dropped, and the part asks: "material cleared entries" never shows Cleared is No.
- A term's definition, its label, aliases and conditions, is never sent to an Intent Provider. The request a provider receives is the same with terms declared or not, for every labelled request, and the provider is called as often. `describeProviderPayload` leaves terms out. The words the User typed are sent as always, a term's word among them.
- With no `houseTerms`, a term's words read as before ("show the big accounts" asks what to filter on). Two narrowings apply to every grid, with terms or without, each found as a wrong view in the held-out sets:
  - An adverb nothing reads, beside a value, a yes/no column, an amount or a date, asks: "accounts largely in taxable", "accounts that are mostly taxable", "accounts roughly over $1m" and "taxable accounts held indirectly" ask about the adverb. Before, each was ready and dropped it. An adverb that says what "only", "all" or "now" says is read as before: "accounts currently at Northgate", "accounts solely at Northgate", "accounts that are fully taxable", "show taxable accounts quickly". So are the adverbs GridCue reads ("only", "exactly", "alphabetically") and one right before a verb ("kindly show").
  - A size or age word sorts only a column that holds an amount or a date. "Which advisor has the largest accounts?", "accounts by advisor, largest first" and "accounts, newest first" ask which column to sort by, also with a `defaultMeasure`. Before, they sorted by Advisor or Account number. "Sort by advisor, largest first" still sorts by Advisor, descending. A column's own name is no "sort" or "order": "accounts by order id, largest first" asks too.
- With terms declared, the requests that read differently are those that hold a term's word, or a word made from one. "Show large taxable accounts" filtered Taxable and dropped "large". It now adds both filters. The Mock Provider asks for the column of an amount beside a term ("large accounts over $5m"); a provider that picks the amount's column gets both filters.

**Text and empty forms** (named filters spec, 5.2; ADR 0023)
- Four forms are read by code, which the provider never decides, each as the words shown and nothing else. `advisor starts with "Av"` (also "starting with", "begins with", "beginning with") filters Advisor starting with “av”. `advisor is exactly "Avery Lane"` (also `exactly`, `=`, "equals", "equal to") filters Advisor to exactly “avery lane”, ignoring letter case. "Accounts with no advisor", `advisor is empty` (also "blank", "missing", "without an advisor", "assigned" or "set" at the end) shows only rows where Advisor is empty. "Accounts that have an advisor" and `advisor is not empty` show the rows where it is not. Before, the first two asked "I'm not sure how to match “av”. Try “containing”." and the others asked what to change, or ended in a different view.
- Exact and starts-with are written only for text columns, and empty only for text, category, date and date-and-time columns. "Custodian is exactly “Northgate”" asks "GridCue can match text only in a text column, and Custodian isn't one." On a number, currency or percent column "no gain" asks "GridCue can't tell whether “no gain” means Unrealized gain is empty or zero. Ask for an amount instead." A yes/no column keeps its reading: "no restricted holdings" still shows Restricted holdings is No. The grid's `rowNoun` is never the column of an empty form: "no accounts over $1m" is unchanged. `advisor is "Lane"` still means containing.
- A column's `allowedOperators` turns a form off: without `eq`, `startsWith`, `isEmpty` or `isNotEmpty`, the request asks ("GridCue can't filter Advisor to exact text here.").
- Preview lines: "Filter Advisor starting with “av”", "Filter Advisor to exactly “avery lane”", "Show only rows where Advisor is empty" and "… is not empty". An exact-text line used to read "Filter Advisor to “avery lane”", and an empty line "Filter Advisor to empty".
- A part with one of these forms is ready only when GridCue places every word in it. "Accounts with no advisor assigned to the new team" asks "I'm not sure what to do with “to” and “new team”. Try rephrasing that part.", and so do "who has no advisor", "advisor is exactly “Avery Lane” about retirement" and "accounts with no advisor sorted by size". "To", "about", "who" and "what" are never placed. A verb read only for columns, such as "pin", is placed only when the plan changes a column, so "advisor starts with “Av”, pin advisor" asks. A form's filter uses its own words only: the same column named again outside them asks unless another change uses it, so "show only advisor for accounts with no advisor" and `show advisor where advisor starts with "Av"` ask about “advisor”.
- A column asked for beside a form is never dropped. A column's name in the singular right after a verb that chooses rows ("show", "find", "view", "give" and the rest), "only", "just", "add" or "hide" asks for that column, with "the", "a", "an", "this", "that", "only", "just", "me", "us", "my" or "our" between them or nothing. The plan must hold a change for it other than a sort, or the part asks: "show only household where advisor is empty", "show household with no advisor" and "find household where advisor is empty" ask "I'm not sure what to do with “household”. Try rephrasing that part." An entity in the plural or after "every", "each" or "all", and the grid's `rowNoun`, name the rows, so "households with no advisor", "show households where advisor is empty" and "show every household with no advisor" are ready. `Hide advisor where advisor is exactly "Avery Lane"` is ready with the hide and the filter, and so is "accounts with no advisor, show only household". A sort by the column, kept from an earlier part or the part's own, is not that change: "show only market value column where advisor is empty, largest gain first" asks.
- A statement in one of these shapes is not a request, and the part asks as before. A form is not read with "my" or "our" before its column ("my advisor is missing"), with a possessive before it ("my accounts' advisor is missing", "the account's advisor is blank"), with "has" or "have" with no "that", "which" or "who" outside quoted text before it that describes the rows ("every account has an advisor", "my accounts have no advisor", "that account has no advisor"), with "every", "each", "all", "any", "this", "that", "these" or "those" before the column of a form that says something of it ("every advisor is empty", "that advisor is missing", `each advisor starts with "Av"`), right after "is", "are", "was", "were", "isn't" or "aren't" before "without", "with no" or "no" ("accounts are without an advisor", "accounts which were without an advisor"), with "which", "what", "whose" or "who" right before its column and no name for the rows before that ("which advisor is missing"), or with only a preposition and the rows after a form that says something of its column ("advisor is empty for every account", "advisor is missing from the account"). A text form said as a statement asks about the words that make it one: `every advisor starts with "Av"` asks about “every”, and `which advisor starts with "Av"` about “which”. "My" and "our" are placed only right before the noun for the rows, when that noun comes before the form, with named values, a yes/no column or a direction or count between ("my restricted accounts with no advisor"); an entity in the singular is no noun for the rows ("my household with no advisor" asks). "Me" and "us" are placed only in a lead-in or right after a verb that chooses rows, and never with "with", "for", "of", "at", "in" or "from" right after them ("include me in accounts with no advisor" asks). Anywhere else they ask: "advisor is missing from my account" asks about “my”, and "advisor is missing for me" about “me”. "Accounts that have an advisor", "which accounts have no advisor", "accounts whose advisor is empty", "advisor is empty for taxable accounts", "my accounts with no advisor", "show us accounts with no advisor", "every account with no advisor" and `all advisors starting with "Av"` are read. Some statements are still read as requests, such as "accounts are all without an advisor" and "for every account, advisor is empty".
- A column named right after a form is that column, as it is before the form: "entries with no counterparty booked after 2026-01-01" filters Booked and Counterparty, as "entries booked after 2026-01-01 with no counterparty" does. An entity word there asks: "accounts with no household advisor" asks about “advisor”. Two columns whose names differ only in punctuation, such as "Vendor Name" and "Vendor-Name", share that name, so a form on it asks.
- A part with no such form is read as before, plain quoted text included, with two new checks (order plan, D4). Each only asks; neither adds a reading:
  - A word for no value outside an empty form ("blank", "blanks", "empty", "empties", "null", "nulls", "missing") asks, since GridCue doesn't read where empty rows go. "Sort by market value, blanks last", "sort by gain with nulls last" and "sort by advisor, empty ones first" sorted and dropped the rest. Each now asks "I'm not sure what to do with “blanks”. Try rephrasing that part.", naming its word. Some requests that already asked now ask in these words: "hide empty columns" asked "There's no column called “empty”. **TanStack Table** (ADR 0031)
- An apply is done only when the table holds it. On a table whose sorting or filters the Host controls (`state` with an `on…Change` handler), `apply` returned before the table had rendered the change. It returned the old Revision, the table then moved to a new one, and undo was refused as if the User had changed the view. Now the adapter waits for the table to hold what it wrote, up to 1,000 ms, and returns the Revision the table has. Undo works. `restore` waits the same way. A table that owns its state still resolves in the same tick, and listeners hear of one apply once.
- A controlled slice with no change handler used to say "View updated." while the table stayed as it was. Now the apply fails after 1,000 ms. When the request wrote only that slice, the message is "The grid couldn't apply that change. Nothing was changed." When it also wrote a slice the table owns, GridCue puts that slice back and says "The previous view is back." Nothing is undoable.
- A change handler must store exactly the value it is given, and set it within 1,000 ms. One that adds to the value, or sets it later, makes the apply fail. The guide says what the User then sees.
- The Revision an apply returns is the one the table had when it first held the write. A change made after that, even in the same tick, makes undo stale, so undo never erases it.
- When a wait fails, the Controller puts the previous view back only if every part of the view still holds its old value or the value the plan wrote. If the User sorts by a header during the wait, their sort stays and the message says the view changed meanwhile. The visible columns are judged as a set, so a write that stops after the column order but before the visibility is still put back.
- The filters are judged grouped by column, as a TanStack table holds them. A failed apply that added a second filter on a column, ahead of another column's filter, was left half applied with "the view changed meanwhile". Now the previous view is back.
- `GridAdapter.apply` and `restore` document the rule, and the shared adapter contract suite gains "applies, then undoes". A custom adapter whose grid updates later must wait for it too. The Site's TanStack and adapter guides say so.

**Counts** (ADR 0027)
- In `applyView`, a row with no value in the first sorted column never fills a count. No value is what a filter's "is empty" means (missing, `null` or empty text), plus `NaN`. "Top 10 by market value" on a column where only 7 rows have a value shows 7. Before, in a descending sort, rows with no value came first and filled the count. A count on a view with no sort still keeps the first rows as they are.
- A count follows its rows. After "top 10 accounts by market value", "sort by advisor", "clear the sort", "only the taxable ones", "accounts over $1m" and "clear the filters" each previewed one line and kept ten rows, a different ten or ten in no order, without saying so. Now each asks "Keep only the first 10 rows of the new view, or show every row?" with "Keep the first 10" and "Show every row", and each answer adds its own Preview line. Grouping, columns, "reset the view" and a request with its own count ("top 5 by gain") don't ask. The rule is `countQuestion`, a pure function of a plan's operations and the view, exported from the root and applied after compiling, so it holds for every provider. Requests that were ready and now ask: a sort change, a sort clear, or a filter add, replace or clear, on a view with a count.
- A count can be cleared and set in the Preview's own words, read by code. "Show every row", "show all rows", "remove the count" and "no count" clear it. "Show only the first 5 rows" sets it. All four were questions before ("What should “show every row” filter on?", "I'm not sure how to compare with “5”"). "Show only the first 5 rows" on a view with no sort asks "First 5 by which column?", and on a grid that lists no `limit.set` ends in "This grid can't show only the first 5 rows." with nothing applied. The words are read in the order they are said: "sort by advisor, then show only the first 5 rows" is ready, while "show only the first 5 rows, then sort by advisor" (the 5 rows on screen, or the first 5 by Advisor?) and count words before "reset the view" ask about that part. A sort or grouping said after a count, while one said before the count is still in effect, would replace the one the count was said with, so the part that set the count is asked about, whether it is count words or "top 10 by …": "sort by gain, show only the first 5 rows, then sort by advisor", "group by custodian, show only the first 5 rows, then group by advisor", "top 10 accounts by market value, sorted by advisor" and "top 5 by gain and sort by advisor" ask "I'm not sure what to do with “…”" about that part. They were ready, with the later sort as a tiebreaker of the earlier one or the later grouping inside the earlier one. The same holds on a grid that lists no `limit.set`, where "top 10 by …" sorts alone with the note: "top 10 by market value, then sort by household" asks there too, where it previewed Household as a tiebreaker of the Market value sort. "Show all accounts" on a view with a filter and a count asks "Show every row, or clear the filters too?".

**Safety** (ADR 0019)
- A ready plan uses everything code read. The compiler's last step turns a plan that leaves an amount, quoted text, date, count or name unused into a question that names it ("I'm not sure what to do with “$1m”. Try rephrasing that part."), with any provider. "Accounts over $1M grouped by custodian." no longer previews the grouping alone.

**Resolution**
- Comparison symbols `>`, `<`, `>=`, `<=`, `=`, `≥` and `≤` are read with or without spaces. "Market value > $1m" filtered to equal $1,000,000.
- "At or above", "at or below", "over or equal to", "greater than or equal to", "less than or equal to", "on or before", "on or after", and after the amount "or more", "or less", "or later", "or earlier", "at most", "at the most", "at least", "max", "minimum", "exactly" and "+" are read. "Since" a date includes that date.
- "No greater than" and "not more than" read as at most; "no lower than" and "not less than" as at least. "Not over", "not above" and `=/=` are asked about.
- An amount is read only when what follows it is the end of the part or something GridCue reads (a name, an amount, a view verb), so "$1M, roughly", "over $1M or so", "$1M with a margin" and "$1M give or take" are asked about. With no comparison word it is "equal to" only when it sits right by its column ("market value $750k", "opened on 2024-01-01", "accounts with 5 positions"); "around $1M" and "!= $1M" are asked about.
- A minus sign, "negative" or "minus" right before an amount makes it negative: "gain below -$50k" filtered to $50,000. A hyphen between two amounts or words is unchanged.
- "Between A and B" and "from A to B" are ranges, lower bound first. A bound with no unit takes the other bound's only when that is certain ("between 10-20%", "between -10 and -5%", "between $1-2m"); "between $1 and 2m" is asked about.

- A column named before an amount it can't hold is asked about: "gain over 10%" filtered Concentration. The grid's `rowNoun`, other entities, and, with no `rowNoun`, a column that holds no amount still mean the rows ("accounts over 10%").
- An amount or quoted text before another change's verb filters too: "accounts over $1M grouped by custodian".
- "Or" between conditions on different columns, or at the start of a part, is asked about, since filters combine with "and": "over $1M or at Northgate" filtered both. "Northgate or Harborline" is still one filter.
- A part that leaves rows out keeps the complement of one simple condition: "hide taxable accounts" keeps the other registration types, "exclude accounts over $1M" keeps at most $1M. Each filtered to the rows named. More than one condition, a second negation, or "except" is asked about.

"Clear the market value filter" clears only that column's filters when the current filters are one "and" list. Each previewed a plain clear. "Remove northgate accounts except trusts" is no clear and is asked about.

Verbs GridCue reads only for columns (add, put, move, pin, arrange, bring, place, shift) count as a view request only when their object is columns ("add the custodian column"); on rows ("move the IRA accounts to Harborline") they are asked about.
- Quoted text is never split by punctuation inside it, and never read as an instruction, one of the Host's values, or a column name outside a column slot (`advisor containing "custodian"`).
- A name declared with a trailing symbol ("account #") is read whole, and words inside a declared name ("Advisor Group") are never read as a verb.
- Amounts in questions are formatted like the preview's ("above 1,000,000").
- "Or later", "and earlier", "at the latest" and the like are read only after a date; after any other amount they are asked about.
- A range borrows a scale only in the compact form from the second bound ("$1-2m"), and a percent sign from the second bound with any join ("between 10 and 20%"). "Between $1m and 2" and "between 5 and 50k" are asked about.
- "Don't show", "never show" and "no longer show" leave rows out like "hide"; "hide accounts where gain is below $0" keeps the other rows instead of hiding Account number.
- A part that stops on "and", "or", "but", "then" or "the" is asked about. A column named with nothing said about it ("and the advisor") is asked about.

"Keep the grouping" or "keep the sort" restores it after a reset. Each question says why. Quoted text in what a clear keeps gets the same word checks as in a new filter: `clear filters except advisor "Lane" exactly` kept Advisor containing “lane”.
- A name ending in a symbol ("Available Cash $") keeps it, and a size word and count inside a name ("Top 10 Holding") are part of it.

"Column" after a column's name, and "name" after one that names another record ("advisor name"), are part of the name.

At the end of the part it reads any of "please", "too", "also", "only" and "as well", then "thanks".

## 0.1.0 (2026-09-25)

The first release.

**Resolution**
- One package, `gridcue`, with the `gridcue/react`, `gridcue/server`, `gridcue/mock` and `gridcue/tanstack-table` entries.
- The Controller runs each request:
  1. normalize it and screen restricted columns;
  2. ask an Intent Provider closed questions;
  3. compile a View Plan, then validate and preview it;
  4. apply it atomically;
  5. undo it on request.
- Deterministic name matching (Mentions), with grammar rules that tell the rows from a column (ADR 0013).
- Precedence rules for competing changes (ADR 0012), and several changes per part through the fan-out questions (ADR 0014).

**Providers**
- The Jev provider has two strategies, `"focused"` and `"fan-out"` (the default), with per-signal toggles (ADR 0015).
- A Mock Provider for keyless development and tests.

**Domain declarations**
- `rowNoun`, column `entity`, and `valueGroups` (ADR 0015).

**Safety**
- View-only: GridCue never changes data.
- Preview before apply.
- Restricted columns are refused before any provider call.
- No provider key ever reaches a browser bundle; `pnpm check:bundles` enforces this.

**Reliability**
- A provider time limit (`providerTimeoutMs`, default 8 s). When it passes, the view returns to idle and the request is kept.
- Apply and undo never stick: a failed write restores the previous view.
- Answering "No" ends with a clear "nothing will change".
- A new filter replaces the current filters unless the request says to add ("also", "only those", "narrow it down"), as sorts and groupings already do, and the Preview names the filters it removes (ADR 0017).
- Undo steps back through every applied change in turn, to the starting view. It stops at a manual change instead of erasing it.
- Nothing in a request is dropped silently. A direction beside another change ("trusts, largest first") asks which column to sort by. When no answer was given on whether a part adds a level ("also group by advisor") or which level is outer ("group by advisor within custodian"), GridCue asks instead of guessing. This happens with the focused strategy, the Mock, or a provider that doesn't ask those questions.
