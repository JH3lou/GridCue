# Troubleshooting

Look up the symptom, check the cause, then fix. Read the linked docs page before changing code.

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Nothing previews; "I'm not sure what to change" | The request's words aren't column labels or aliases | Add aliases and `enumValues` ([Describe your domain](https://gridcue.dev/docs/get-started/describe-your-domain)) |
| "Which column should be sorted by?" for "largest first" | No column name in the request, or `rowNoun` unset | Expected on the Mock. Set `rowNoun`; with Jev, the provider often picks the column. |
| "Keep only the first 10 rows of the new view, or show every row?" | The view has a count and the request changes the sort or the filters | Expected: pick one. "Show every row" clears the count at any time ([Requests](https://gridcue.dev/docs/concepts/requests)) |
| "Count not applied: this grid can't show only the first 10" for "top 10 accounts by market value", or "This grid can't show only the first 5 rows." for "show only the first 5 rows" | A Query Adapter without `countBeforePaging: true`, a TanStack Table adapter with no `renders: ["count"]`, so it doesn't list `limit.set`, or one whose table turned on a manual setting or `getSubRows` after the adapter was made | On a Query Adapter: expected. Set `countBeforePaging: true` only when the server sorts, keeps the first N rows, and only then pages, and its Data Query keeps the rows `applyView` keeps ([Adapters](https://gridcue.dev/docs/api/adapters#countbeforepaging)). Never to make the request pass: on a server that pages first, "top 10" would show every row. On TanStack: expected until the table shows the first rows. Then register `gridcueCountFeature` and `gridcueCountRowModel(createFilteredRowModel())` and set `renders: ["count"]` ([Adapters](https://gridcue.dev/docs/api/adapters#gridcuecountfeature)). Never on a table that pages, sorts, filters or groups on a server, or has sub-rows: `INPUT_CONFIG` names the setting. If the count stopped after the table turned on `manualPagination`, `manualSorting`, `manualFiltering`, `manualGrouping` or `getSubRows`, turn that setting off when the table holds all its rows itself, and the count it holds applies again; otherwise the table can't show a count, and "top 10" sorts with the note. |
| A Query Check case fails: its message names the case and the missing and extra ids | The app's Data Query translates a filter another way than GridCue means it, such as `not equal` dropping empty cells or a text match that ignores case on one side only | Follow the table of what each filter means in [Rows on a server](https://gridcue.dev/docs/guides/rows-on-a-server#3-what-each-filter-means), and fix the Data Query. Never edit the case or the rows to make it pass ([Testing](https://gridcue.dev/docs/api/testing)) |
| "This grid can't show totals." for "total market value by advisor" or "remove the totals" | The adapter has no `renders: ["totals"]`, so it doesn't list `aggregation.set`. A Query Adapter never lists it | On a Query Adapter: expected, always. A total over rows on a server is a Data Query of its own, and `renders: ["totals"]` throws `INPUT_CONFIG` there. Elsewhere: expected until the table draws totals. Then set `renders: ["totals"]` and draw them. On TanStack, register `rowAggregationFeature` and put `gridcueAggregationFn` and `gridcueAggregationValue` on `defaultColumn` first ([Adapters](https://gridcue.dev/docs/api/adapters#gridcueaggregationfn)). Never turn it on only to make the request pass. |
| "Concentration can't be totalled. Show its average instead?" for "total concentration" | A sum fits a number or currency column. A percent column takes an average only | Expected: answer Yes for the average. |
| "“total” is a name in this grid, so GridCue can't tell what “total” asks for." for "group by owner with totals", or what “total units” asks for in "sort by total units" | A column has "total" or "sum" as an alias, and the grid draws totals, so the word may name the column or ask for a total | Expected. If Users mean totals more often than the column, drop that alias. |
| "GridCue can't group by Unrealized gain and show its total too." | The view would total a column it groups by, and a group row shows its own value there | Expected: total another column, or group by another one. |
| "I'm not sure what to do with “to” and “new team”." for "accounts with no advisor assigned to the new team", or any request with "starts with", "exactly" or "no <column>" and an extra word | A part with a text or empty form is ready only when every word in it is one GridCue places | Expected: ask for the form alone, or put the rest in its own part. Don't add the word as an alias ([Requests](https://gridcue.dev/docs/concepts/requests#text-forms-and-empty-values)) |
| "I'm not sure what to do with “household”." for "show only household where advisor is empty" | A column's name in the singular right after a verb that chooses rows ("show", "find", "give me" and the rest), "only", "just" or "hide", with "the", "a" or "an" between or nothing, asks for that column, and the part's plan holds only the filter | Expected: GridCue never drops the column. Say the column change as its own part ("accounts with no advisor, show only household") or name the rows ("households with no advisor") |
| "I'm not sure what to do with “my”." for "advisor is missing from my account", “empty” for "every advisor is empty", “missing” for "which advisor is missing", or "I'm not sure what to change for …" for "accounts are without an advisor" or "that account has no advisor" | The request says something instead of asking for rows. "My" and "our" are read only right before the noun for the rows ("my accounts …", "my restricted accounts …") before the form, and "me" and "us" only in a lead-in or right after a verb that chooses rows ("show me", "list us"), never before "in", "for" or another preposition ("include me in …"). A form is not read after "is" or "are" right before "without" or "no", after "has" or "have" with no "that", "which" or "who" that describes the rows, after a question word right before its column with no rows named before it, or with only a preposition and the rows after it ("advisor is empty for every account") | Expected. Ask for the rows: "my accounts with no advisor", "accounts where advisor is empty", "accounts whose advisor is empty", "which accounts have no advisor?" |
| "GridCue can match text only in a text column" for `custodian is exactly "Northgate"`, or "GridCue can't tell whether “no gain” means … empty or zero" | "Exactly" and "starts with" need a text column, and "empty" isn't read for number, currency or percent columns | Expected. Ask for the value ("Northgate") or an amount ("gain over $50k") |
| "GridCue can't filter Advisor to exact text here." (or "…by how it starts here.", "…rows where it is empty here.") | The column's `allowedOperators` leaves out `eq`, `startsWith`, `isEmpty` or `isNotEmpty` | Expected if that was on purpose. Otherwise add the operator back ([schema](https://gridcue.dev/docs/api/schema)) |
| A filter previews but the table doesn't change | `gridcueFilterFn` isn't the table's default filter function | `defaultColumn: { filterFn: gridcueFilterFn }` ([Vite and TanStack Table](https://gridcue.dev/docs/guides/vite-tanstack)) |
| Undo stops working after the table changes | The controller is rebuilt on each render | Create it once with `useState(() => …)`, not `useMemo` on `table` |
| "The grid couldn't apply that change. Nothing was changed." on a TanStack table whose state the Host controls | A controlled slice (sorting, filters, and so on) has no change handler, or its handler sets state only after a fetch. The table doesn't hold the change within 1,000 ms. A handler that sets state later still changes the table after this message, and that change can't be undone. | Give every controlled slice its `on…Change` handler, and set state first, fetch after ([Vite and TanStack Table](https://gridcue.dev/docs/guides/vite-tanstack)) |
| "…the view changed meanwhile, so GridCue left it as it is." after about a second, on a controlled TanStack table, when no one changed the view | The slice's change handler stores something other than what it is given, such as an added tiebreaker sort, so the table never holds GridCue's value | Store exactly the value the handler is given. Adjust it where you read it, such as in the fetch ([Vite and TanStack Table](https://gridcue.dev/docs/guides/vite-tanstack)) |
| Undo refused on a controlled table | Older GridCue returned before the table had rendered the change, so the Revision was already out of date | Update `gridcue`. An apply now returns the Revision the table holds. |
| "The view changed since this preview" | The User changed the table between Preview and Apply | Expected: preview again. GridCue never overwrites a manual change. |
| "That request mentions a restricted column" | The request named a restricted column or alias | Expected. Don't unrestrict a column to make a request pass. |
| `gridcue/server` throws in the browser | Server code imported into a client component | Keep `gridcue/server` in server routes only; the browser uses `createRemoteProvider` ([Server Handler recipes](https://gridcue.dev/docs/guides/server-handler)) |
| `INPUT_CONFIG`: "The Jev provider needs @typesafe-ai/sdk" | The SDK isn't installed where the server runs | `npm i @typesafe-ai/sdk` in the server's package |
| The command bar shows "Couldn't interpret that request" | The endpoint failed: missing key, 401 or 429, or the route isn't mounted | Check the server logs and the network tab ([Protect the endpoint](https://gridcue.dev/docs/guides/protect-the-endpoint)) |
| "That took too long" | The provider exceeded `providerTimeoutMs` (8 s by default) | Check the endpoint's latency; raise the limit only if needed |
| Too many questions with Jev | `strategy: "focused"`, or sparse aliases | Use the default `"fan-out"`, and add aliases ([Choosing a strategy](https://gridcue.dev/docs/guides/choosing-a-strategy)) |
| "GridCue can't leave out “large” yet." for "accounts that aren't large" or "hide large accounts", or "“large” stands for rows, not a column." for "sort by large" | "Large" is a House Term: a term can't be left out, and it names rows, never a column | Expected. Ask for the rows to keep ("market value at or below $1,000,000") or name a column ([Requests](https://gridcue.dev/docs/concepts/requests#house-terms)) |
| `defineSchema` throws `INPUT_SCHEMA`: `House Term "Large": the name "Large" is also a name of …`, `… is one of GridCue's own words.` or `… holds “top”, …` | A term's label or alias is already a column's, value's, Value Group's, `rowNoun`, `entity`, another term's, or a GridCue word, or holds one of those, or an amount, among its words | Pick another word for the term. Don't remove the other name ([schema](https://gridcue.dev/docs/api/schema#houseterms)) |
| "Did you mean Advisor: Avery Lane?" for "Lane's accounts", or "6 Advisor values contain “lee”. Type the full name." | One word of a value asks which was meant, and six or more values ask for the full name | Expected. Choose, or type the whole name ([Requests](https://gridcue.dev/docs/concepts/requests#local-values)) |
| "Avery Lane is a value in Advisor, not a column.", "GridCue can't leave out “avery lane” yet." or "I'm not sure what to do with “by”." for "accounts held by Avery Lane" | A Local Value is read only as rows to keep: not where a column goes, not left out, and “by” is placed only beside a sort or a group | Expected. Say "accounts for Avery Lane" ([Requests](https://gridcue.dev/docs/concepts/requests#local-values)) |
| A request that names a person or household asks what to filter on | `localValues` isn't set, or the column isn't named in it, or a paged grid's function returns only the page | Add the column to `localValues`; for a paged grid return the Host's own list ([Describe your domain](https://gridcue.dev/docs/get-started/describe-your-domain#local-values)) |
| `createGridCue` throws `INPUT_CONFIG`: "localValues can read only text columns, …", "… is restricted.", "… it may not be filtered.", "… its allowedOperators leave out “eq” or “in”." or "… not a column of this grid." | A `localValues` key is a column that isn't an exposed text column of the schema that can be filtered to exact text | Name a text column that is not restricted, and if it sets `allowedOperators`, add `eq` and `in` only when the grid can filter that column to exact text ([`createGridCue`](https://gridcue.dev/docs/api/create-grid-cue#local-values)). Don't unrestrict a column |
| "This grid can't sort rows.", "…filter rows.", "…clear filters.", "…group rows.", "…hide columns.", "…show hidden columns.", "…reorder columns." or "…reset the view.", and nothing applies, the request's other parts included | The Host's Query Adapter was built with `without` naming that operation | Expected while it is there. Take the operation out of `without` only if the Data Query can carry it out ([Adapters](https://gridcue.dev/docs/api/adapters#without)) |
| `createQueryAdapter` throws `INPUT_CONFIG`: "without names …, which isn't an operation the Query Adapter lists.", "renders names “totals”: …", "renders names “count”: …" or "countBeforePaging must be true or false, …" | `without` holds a typo or an operation the adapter doesn't list by default (`limit.set`, `columns.pin`, `density.set`, `aggregation.set`), or `renders` names something a Query Adapter doesn't take | Fix the name. To keep a count off, leave `countBeforePaging` out; to keep pins or density off, leave them out of `renders`. Totals are never listed on a Query Adapter ([Adapters](https://gridcue.dev/docs/api/adapters#without)) |
| `createQueryAdapter` or `setState` throws `INPUT_CONFIG`: "initialState holds …" or "setState would hold …, which this grid can't keep." `restore` fails with `ADAPTER_NOT_APPLICABLE`: "This snapshot holds …" | The View State holds a count without `countBeforePaging`, totals, pins without `"pinning"` in `renders`, or a density without `"density"`, often from a view saved on another grid, such as in the URL | Take that part out of the View State first, or turn the option on only if the server and table really do it ([Adapters](https://gridcue.dev/docs/api/adapters#what-it-never-holds)) |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "createAgGridAdapter needs api: the grid's api, from onGridReady or createGrid." | `api` is missing or not an object, often read before the grid is ready | Create the adapter inside `onGridReady` with `e.api`, or from the api `createGrid` returns ([AG Grid](https://gridcue.dev/docs/guides/ag-grid)) |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "The grid's api has no …, which GridCue uses. GridCue's AG Grid adapter is tested with AG Grid Community 34, 35 and 36." | The api is from an AG Grid older than 34, or isn't AG Grid's api | Use AG Grid Community 34, 35 or 36. Never stub the missing call |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "The grid is destroyed. Create the adapter from a grid that is showing." | The grid was destroyed before the adapter was made, as React strict mode does to its first grid | Create the adapter from the `onGridReady` of the grid that stays |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "The schema names “…”, which is not a column of this grid. Give the column that colId, or leave it out of the schema." | A schema column has no column in the grid with that `colId` (or `field`) | Give the column definition that `colId`, or leave the column out of the schema. Don't rename the schema's ID to match a label |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "The grid can't hold GridCue's filters: the column “…” has no filter, so it doesn't carry gridcueColumnDefs' settings. …" | The grid's `columnDefs` aren't `gridcueColumnDefs(schema, columnDefs)`, or the column sets `filter: false` | Give the grid `columnDefs={gridcueColumnDefs(schema, columnDefs)}`, built once from the adapter's schema, or take `filter` off that column's capabilities in the schema ([AG Grid](https://gridcue.dev/docs/guides/ag-grid#3-give-the-grid-gridcuecolumndefs)) |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "… has a filterValueGetter, so AG Grid filters another value than its cell …" or "… has a valueGetter, so AG Grid filters a value GridCue doesn't read from the row …" | AG Grid would filter a value GridCue's filters don't mean, such as an enum's label | Take `filter` off that column's capabilities in the schema (`schemaFromAgGrid` does), or drop the getter and give the column a `field` that holds the value. Never remove the check |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "… has a filter of its own, which GridCue can't write. …" | The column's `filter` is a custom component or an Enterprise filter | Use AG Grid's own text, number or date filter on it, or take `filter` off the column's capabilities in the schema |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "… holds … values in the schema, but its cellDataType is … / it uses AG Grid's … filter. Set cellDataType on the column to match, …" | The column's AG Grid filter isn't the one its schema kind needs, often a number or date column with no `cellDataType` | Set `cellDataType` (`"number"`, `"date"` and so on) on the column, or fix its kind in the schema |
| `createAgGridAdapter` throws `INPUT_CONFIG`: "… doesn't carry gridcueColumnDefs' filter settings: its filterParams.… isn't the one gridcueColumnDefs gives it for this schema. …" | The column's own `filterParams` replaces a setting `gridcueColumnDefs` gives (such as `filterOptions`, `textFormatter` or `includeBlanksInEquals`), or `gridcueColumnDefs` was built from another schema | Build `gridcueColumnDefs` from the schema the adapter gets, and leave that key out of the column's `filterParams`. Never loosen the check |
| "AG Grid can't hold an OR across two columns …", "… a list of values beside another filter on the same column …" or "… AND and OR filters on the same column …" (`ADAPTER_UNSUPPORTED_FILTER`) | The View State's filters can't be one AG Grid filter model | Expected: nothing changed. Ask for one filter at a time |
| "… holds a filter GridCue can't read, so GridCue leaves it as it is and can't add one there." (`ADAPTER_UNSUPPORTED_FILTER`) | A column holds a filter from a custom filter component, or menu text GridCue can't mean, such as an enum filter naming no value or label | Expected. Clear that filter in the grid first |
| "AG Grid didn't hold the change, so nothing was changed." (`ADAPTER_FAILED`) | AG Grid dropped or cut short what GridCue wrote | Check the column carries `gridcueColumnDefs`' settings and the AG Grid version is 34, 35 or 36. Don't retry in a loop |
| "This grid can't group rows." on an AG Grid | AG Grid Community can't group | Expected. Pins, totals, counts and density aren't listed either |
| "Couldn't read this grid's values. The view hasn't changed." (`INPUT_LOCAL_VALUES`) | A `localValues` function threw or returned something that isn't an array | Fix the function. It is synchronous and returns an array of the column's values |
